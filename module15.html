Module 15: Cloud Computing

Section 1: Cloud Computing Fundamentals

Cloud computing = delivery of computing services (servers, storage, databases, networking, software) over the Internet.

Key Characteristics (NIST)

  • On-demand self-service: Resources provisioned automatically without human interaction
  • Broad network access: Available over network via standard mechanisms
  • Resource pooling: Multi-tenant model with resources shared across customers
  • Rapid elasticity: Resources scale outward/inward rapidly
  • Measured service: Resource usage monitored, controlled, and reported

Cloud Service Models (SPI Model)

  • SaaS (Software as a Service): Applications delivered over Internet. No infrastructure management. Examples: Gmail, Salesforce, Office 365
  • PaaS (Platform as a Service): Hardware/software tools delivered over Internet. Developers build apps. Examples: Google App Engine, Heroku, Azure App Services
  • IaaS (Infrastructure as a Service): Virtualized computing resources over Internet. Full control. Examples: AWS EC2, Azure VMs, Google Compute Engine

Responsibility by Model

SaaS: Provider handles everything except data and user access management.

PaaS: Provider handles infrastructure; customer manages apps and data.

IaaS: Customer manages OS, middleware, runtime, data, applications; provider handles physical hardware.

Section 2: Cloud Deployment Models

  • Public Cloud: Services offered over public Internet. Owned by third-party cloud provider. Examples: AWS, Azure, GCP
  • Private Cloud: Dedicated resources for single organization. On-premises or hosted. Full control.
  • Hybrid Cloud: Combination of public and private clouds. Data/apps can move between them.
  • Community Cloud: Shared by multiple organizations with common concerns (security, compliance, policy)

Section 3: Major Cloud Providers

  • AWS: EC2, S3, RDS, Lambda, DynamoDB, CloudFront
  • Microsoft Azure: Virtual Machines, Blob Storage, SQL Database, Functions, Cosmos DB
  • GCP: Compute Engine, Cloud Storage, BigQuery, Dataflow
  • IBM Cloud: Enterprise focus with Watson AI integration
  • Oracle Cloud: Database-focused cloud services

Section 4: Cloud Security Controls

Shared Responsibility Model

CLOUD PROVIDER secures: Physical infrastructure, global network, hypervisor.

CUSTOMER secures: Data, identity management, OS/network configuration, application security.

Cloud Security Best Practices

  • IAM: Least privilege, MFA, role-based access control (RBAC)
  • Data encryption: At rest (AES-256) and in transit (TLS 1.2+)
  • Network security: VPCs, security groups, NACLs, WAF
  • Logging and monitoring: CloudTrail, GuardDuty, Security Hub
  • Compliance frameworks: SOC 2, ISO 27001, HIPAA, PCI DSS, FedRAMP

Section 5: Cloud Attacks and Vulnerabilities

Common Cloud Attack Vectors

  • Data Breaches: Exposed storage buckets (S3), misconfigured permissions
  • Identity Theft: Compromised credentials, weak IAM policies
  • API Exploitation: Insecure APIs, lack of rate limiting
  • Hijacking: VM escape, hypervisor attacks, side-channel attacks
  • Insider Threats: Malicious employees or contractors
  • Shared Technology Vulnerabilities: Multi-tenant isolation failures

Cloud Misconfiguration Attacks

  • Open Storage Buckets: AWS S3, Azure Blob containers exposed publicly
  • Default Passwords: Unchanged default credentials on cloud services
  • Overly Permissive IAM: Admin access granted to too many users

Section 6: Cloud Forensics and Legal Issues

Challenges: Data location, Volatile evidence, Multi-tenancy, Lack of physical access

Legal Considerations: Data sovereignty, CLOUD Act, GDPR

Section 7: Notable Cloud Security Incidents

Capital One Breach (2019)

Planned Security exploited AWS misconfiguration via WAF vulnerability. 100 million customers affected.
