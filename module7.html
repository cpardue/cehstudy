Module 7: Denial of Service

Section 1: DoS Fundamentals

Denial of Service (DoS) = an attack that prevents legitimate users from accessing a service or system. The goal is to make the machine/resource unavailable to its intended users.

Types of DoS Attacks

  • Traditional DoS: Single source attacks (ping flood, smurf, SYN flood, Teardrop, etc.)
  • Distributed DoS (DDoS): Multiple sources attack simultaneously using a botnet

DoS Attack Categories

  • Volume-based: Measures bandwidth (bps) — e.g., UDP floods, ICMP floods, amplification attacks
  • Protocol-based: Consumes server resources (connection state tables) — e.g., SYN floods, Ping of Death, Slowloris
  • Application Layer: Targets specific application vulnerabilities — e.g., HTTP flood, SQL injection leading to crash

DoS Attack Goals

  1. Kill the machine: Crash the system completely
  2. Bog down resources: Consume all available resources (bandwidth, CPU, memory)
  3. Exploit programming errors: Trigger bugs that cause the application to crash

DoS Attack Vectors

  • Network-based: Target network infrastructure (routers, firewalls, load balancers)
  • Application-based: Target web applications (HTTP flood, SQL injection)
  • Botnet-based: Use compromised machines (zombies) to launch DDoS

DoS Attack Tools

  • Trinoo: Distributed DoS tool using a master/slave architecture. Master sends commands to agents (daemons).
  • Multipinger: Sends ICMP echo requests to multiple hosts simultaneously.
  • WinNuke: Sends out-of-band (OOB) data to Windows systems triggering blue screen of death.
  • Bo: Distributed attack tool using master/slave architecture. Uses UDP port 27665 by default.
  • LophtCrack: Can perform DoS against Windows domain controllers.
  • XDAT (XOIC DOS Attack Tool): Sends multiple TCP RST packets to crash target.
  • TFN / TFN2K / DDOS: Trojan Distributed Denial of Service tools. Support multiple attack types including ICMP flood, UDP flood, SYN flood, etc.
  • Smurf Attack Tool: Sends ICMP echo requests to broadcast address with spoofed source IP.
  • Ncrack: Network cracker that can be used for DoS against authentication services.

Section 2: Common DoS Attack Techniques

Ping of Death

Sends an oversized ICMP packet (>65,535 bytes). When the target reassembles the fragmented packet, it exceeds the maximum IP packet size, causing system crash or reboot.

Mitigation

  • Fragment inspection: Check fragment sizes before reassembly
  • ICMP rate limiting
  • Block oversized packets at the firewall

SYN Flood

Exploits the TCP three-way handshake. Attacker sends many SYN requests but never completes the handshake with ACK. Server's connection table fills up, preventing legitimate connections.

SYN Flood Flow

  1. Attacker sends SYN to server
  2. Server responds with SYN-ACK
  3. Attacker never sends ACK (or uses spoofed IP)
  4. Server waits for timeout, filling connection table

Mitigation

  • SYN cookies: Server encodes state in ACK sequence number instead of allocating resources
  • Connection rate limiting: Limit SYN requests per second from single IP
  • Increase backlog queue: Increase max pending connections
  • Decrease timeout: Reduce time to wait for ACK

Teardrop Attack

Sends malformed IP fragments with overlapping offset values. When the target tries to reassemble, it crashes due to the error.

Smurf Attack

Attacker sends ICMP echo requests (pings) to a broadcast address with a spoofed source IP (the victim). All hosts on the network reply to the victim, overwhelming it.

Requirements

  • IP address of the victim
  • ICMP protocol
  • Broadcast address of the network

Mitigation

  • Disable IP broadcast forwarding on routers
  • Block incoming traffic with broadcast source addresses
  • Implement ingress filtering (BCP 38)

Land Attack

Sends a SYN packet where the source IP and destination IP are both set to the target's IP address. Can cause the system to loop or crash.

Christmas Tree Attack (Xmas Tree)

Sends a TCP packet with all flag bits set (URG, ACK, PSH, RST, SYN, FIN). Named after a Christmas tree because all lights are on. Different OS handle this differently — some may crash.

Jolt2 Attack

Exploits the UDP-based Jarvis protocol. Sends specially crafted JOLT packets to exploit vulnerabilities in TCP/IP stacks of various operating systems.

Buffer Overflow DoS

Sends more data to a buffer than it can hold, causing overflow into adjacent memory spaces. Can crash services like FTP, SMTP, HTTP servers.

Slowloris

Opens multiple connections to a web server and keeps them open by sending partial HTTP requests with slow intervals. The server's connection pool fills up, denying service to legitimate users.

Mitigation

  • Set strict timeout limits for incomplete requests
  • Limit max connections per IP address
  • Use reverse proxies (e.g., Nginx, Cloudflare)

HTTP Flood

Sends massive HTTP GET/POST requests to overwhelm a web server. Difficult to distinguish from legitimate traffic.

Mitigation

  • Web Application Firewall (WAF)
  • Rate limiting per IP/user
  • CAPTCHA challenges
  • CDN-based protection (Cloudflare, Akamai)

NTP Amplification Attack

Type of DDoS amplification attack. Attacker sends NTP requests with spoofed source IP to NTP servers configured in "monlist" mode. Servers respond with much larger responses to the victim.

Mitigation

  • Disable NTP monlist command (version 2)
  • Rate-limit NTP responses
  • Implement ingress/egress filtering

DNS Amplification Attack

Similar to NTP amplification. Attacker sends DNS queries with spoofed source IP to open DNS resolvers. Response is much larger than the query.

Mitigation

  • Disable open DNS recursion
  • Implement response rate limiting (RRL)
  • Block traffic with spoofed source addresses

Section 3: Botnet-Based DDoS

Botnet = network of compromised computers (bots/zombies) controlled by an attacker (botmaster). Used to launch large-scale DDoS attacks.

Botnet Architecture

  • C&C (Command and Control): Centralized server sends commands to bots
  • P2P (Peer-to-Peer): Decentralized — bots communicate with each other
  • Hybrid: Combination of centralized and decentralized approaches

Botnet Lifecycle

  1. Infection: Bots are infected via malware, exploits, phishing
  2. C&C Establishment: Bot connects to command and control server
  3. Attack Execution: Botmaster sends commands to launch DDoS
  4. Cleanup: Bot removes traces or waits for next command

Botnet Detection Methods

  • Traffic analysis: Detect unusual traffic patterns (sudden spikes)
  • Behavioral analysis: Monitor for unusual bot behavior
  • Domain Generation Algorithms (DGA): Detect domains generated by malware for C&C
  • Blacklisting: Block known botnet IPs/domains

Botnet Mitigation

  • ISP-level filtering and blackholing
  • Sinkholing: Redirect C&C traffic to controlled servers
  • Take down botnet infrastructure (law enforcement)
  • Use DDoS protection services (Cloudflare, Akamai, AWS Shield)

Notable Botnets

  • Mirai: IoT botnet that infected cameras, routers. Launched massive DDoS against Krebs on Security and Dyn DNS (2016).
  • Emotet: Banking trojan turned botnet infrastructure
  • Zeus (Zbot): Banking trojan with botnet capabilities
  • Srizbi: Email-focused botnet for spam distribution

Section 4: DoS Countermeasures

Network-Level Defenses

  • Ingress/Egress Filtering (BCP 38/84): Block packets with spoofed source addresses
  • Rate Limiting: Limit number of requests from single source
  • Blackholing (uRPF): Drop all traffic to/from attacked IP
  • ICMP Rate Limiting: Restrict ICMP packet rate
  • SYN Cookies: Protect against SYN flood attacks
  • Load Balancing: Distribute traffic across multiple servers

Host-Level Defenses

  • Apply OS patches and updates
  • Configure firewall rules to block suspicious traffic
  • Disable unused services and ports
  • Implement intrusion detection/prevention systems (IDS/IPS)
  • Monitor system resources for anomalies

Application-Level Defenses

  • Web Application Firewall (WAF)
  • Input validation and sanitization
  • Rate limiting per user/session
  • CAPTCHA for suspicious requests
  • Content Delivery Network (CDN) distribution

Cloud-Based DDoS Protection

  • AWS Shield: Managed DDoS protection for AWS resources
  • Cloudflare: CDN-based DDoS mitigation with global network
  • Akamai: Enterprise-grade DDoS protection services
  • Azure DDoS Protection: Microsoft's cloud-based protection

Incident Response for DoS

  1. Identify: Confirm DoS attack and determine type
  2. Contain: Implement immediate mitigation (blackholing, rate limiting)
  3. Eradicate: Block attack sources, apply patches
  4. Recover: Restore normal operations
  5. Lessons Learned: Document and improve defenses

DoS Testing Tools

  • LOIC (Low Orbit Ion Cannon): Open-source DoS tool
  • HOIC (High Orbit Ion Cannon): Enhanced version of LOIC with multiple attack presets
  • SlowHTTPTest: Tests resilience against application-layer DoS (Slowloris, Slow POST)
  • GoldenEye: Python-based DoS tool targeting HTTP layer
  • AB (Apache Bench): Can be used for load testing/DoS simulation

Section 5: DoS Attack Scenarios and Case Studies

2016 Dyn Attacks (Mirai Botnet)

The Mirai botnet launched one of the largest DDoS attacks in history against Dyn, a major DNS provider. This affected Twitter, Reddit, Netflix, GitHub, and many other sites.

  • Attack vector: IoT devices (cameras, DVRs, routers)
  • Peak traffic: ~1.2 Tbps
  • Impact: Major internet outage across the US and Europe
  • Source code leaked: Led to multiple Mirai variants

2018 GitHub Attack

  • Peak traffic: 1.35 Tbps
  • Attack type: NTP amplification
  • Duration: 20 minutes

2016 Krebs on Security Attack

  • Peak traffic: 620 Gbps
  • Attack type: Mirai botnet DDoS
  • Target: Security journalist Brian Krebs' blog

APAC Gaming Industry Attack (2023)

  • Peak traffic: 856 Gbps
  • Attack type: UDP flood
  • Target: Asian Pacific gaming industry

DoS for Distraction

DoS attacks can be used as a smokescreen to distract security teams while a more damaging attack occurs (e.g., data exfiltration, system compromise).
