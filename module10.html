Module 10: Evading IDS, Honeypots, and Firewalls

Section 1: IDS Fundamentals

Intrusion Detection System (IDS) = a device or software application that monitors network and/or system activities for malicious activities or policy violations.

Types of IDS

  • NIDS (Network-based): Monitors traffic across the entire network. Placed at network perimeter.
  • HIDS (Host-based): Monitors a single host for suspicious activities. Uses file integrity checking, log analysis, and system calls.
  • Network Behavior Analysis (NBA): Detects anomalous traffic patterns that may indicate attacks.

Detection Methods

  • Signature-based detection: Matches known attack signatures/patterns. Effective against known threats but misses zero-day attacks.
  • Anomaly-based detection: Establishes baseline network behavior and flags deviations. Can detect unknown attacks but may have false positives.

IDS Placement

  • Outside firewall (monitors external threats)
  • Inside firewall (monitors internal threats)
  • Beyond firewall (monitors traffic before it reaches the network)

IDS Limitations

  • Cannot stop attacks (only detects and alerts)
  • Encrypted traffic cannot be inspected without decryption
  • High-speed networks may overwhelm the IDS
  • Signature-based systems miss zero-day attacks

Section 2: Evading IDS

IP Fragmentation

Splitting packets into smaller fragments to evade signature-based detection. The IDS may reassemble fragments differently than the target system, or fail to reassemble at all.

# Using fragment-spray tool
fragroute -f config.txt target_ip

Mitigation

  • Enable IP reassembly on the IDS
  • Use stateful firewalls that reassemble before inspection

TCP Sequence Prediction

Predicting TCP sequence numbers to hijack sessions without detection. Modern systems use random sequence numbers making this difficult.

Encryption and Tunneling

Encrypting attack traffic so the IDS cannot inspect the payload. Common methods include:

  • Tunneling ICMP packets (ping tunneling)
  • Using DNS tunneling to exfiltrate data
  • Encapsulating traffic in SSL/TLS
  • Using SSH tunnels

Source Route Option

The IP header contains a source route option that specifies the path packets should take. Attackers can use this to bypass network-based security controls.

Segmentation Overrun

Sending small, non-overlapping TCP segments that individually appear harmless but form a complete attack when reassembled.

Time-Based Evasion

Sending attacks slowly over extended periods to avoid triggering time-based detection thresholds.

OS Fingerprinting to Avoid Detection

Understanding the target OS helps craft attacks that are less likely to be detected. Different OS handle malformed packets differently.

Character Substitution / Encoding

Using encoding techniques (URL encoding, hex encoding, Unicode) to obscure attack payloads from signature-based IDS.

Jumbo Frames

Sending oversized Ethernet frames (>1500 bytes). Some IDS systems cannot handle jumbo frames and may drop them for inspection.

Section 3: Honeypots and Honeynets

Honeypot = a decoy system designed to attract attackers and study their behavior. Contains no legitimate value but appears attractive.

Types of Honeypots

  • Research honeypots: Used for academic research, studying attacker techniques (e.g., Mule)
  • Production honeypots: Deployed in organizations to protect real systems and detect intrusions

Honeypot Categories

  • Low-interaction: Simulate services only. Safer but less information (e.g., Honeyd, Kojoney)
  • High-interaction: Full operating systems. More information but higher risk of being used against the organization

Honeynet

A network of honeypots designed to attract and study attackers. Can simulate entire corporate networks.

Countermeasures Against Honeypots

  • TCP fingerprinting: Compare responses with known OS fingerprints
  • Sending NULL TCP scan: Honeypots may respond differently to NULL scans than real systems
  • Checking for unusual services: Services that shouldn't exist on normal systems
  • Attempting privilege escalation: Honeypots may have weak default credentials

Section 4: Firewall Fundamentals

Firewall = a network security device that monitors and controls incoming and outgoing network traffic based on predetermined rules.

Types of Firewalls

  • Packet-filtering firewall: Filters packets based on source/destination IP, port, and protocol (Layer 3)
  • Stateful inspection firewall: Tracks active connections and makes decisions based on context (Layer 3-4)
  • Application-layer firewall (WAF): Inspects application-level data (Layer 7)
  • Next-generation firewall (NGFW): Combines traditional firewall with IDS/IPS, application awareness, and deep packet inspection

Firewall Configurations

  • Perimeter firewall: Protects the network boundary
  • Internal firewall: Segments internal networks
  • Host-based firewall: Installed on individual hosts (Windows Firewall, iptables)

Section 5: Evading Firewalls

TCP Port Scanning Techniques

Bypassing firewall rules by using techniques that avoid detection:

  • FIN scan: Sends FIN packet without establishing connection. Some firewalls don't track this.
  • Idle/Zombie scan: Uses a third-party system to mask the real IP address
  • Window scan: Exploits TCP window size differences to determine port state

IP Spoofing

Sending packets with a fake source IP address to bypass IP-based firewall rules.

TCP Flag Manipulation

Setting unusual combinations of TCP flags to bypass stateful firewalls:

  • SYN/FIN together (invalid combination)
  • NULL scan (no flags set)
  • Xmas scan (FIN, PSH, URG set)

TCP Session Hijacking

Taking over an established TCP session to bypass firewall rules that trust the connection.

Firewall Evasion Tools

  • Scapy: Python-based packet manipulation tool
  • fragroute: Intercepts, translates, and modifies packet traffic before it reaches the target
  • iptablesspray: Fragments packets to evade firewall detection

Section 6: Firewall Countermeasures

Best Practices

  • Implement defense in depth (multiple firewall layers)
  • Regularly update and patch firewall firmware
  • Use stateful inspection firewalls
  • Implement deep packet inspection
  • Log and monitor all firewall traffic
  • Apply least-privilege principle to rules
  • Regularly audit and clean up firewall rules

IDS/IPS Integration

  • Deploy IDS/IPS behind firewalls for deeper inspection
  • Correlate alerts from firewalls, IDS, and SIEM
  • Use intrusion prevention systems (IPS) to actively block threats
