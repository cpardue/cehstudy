Module 5: Vulnerability Analysis

Section 1: Vulnerability Research & Scanning Types

Vulnerability research helps identify vulnerabilities which could compromise the system.

Scanning Types

  • Active scanning: Interacting directly with the target network to discover vulnerabilities
  • Passive scanning: Discovering vulnerabilities without direct interaction with the target network

Section 2: Vulnerability Categories

  • Misconfiguration, Default installations, Buffer overflows
  • Unpatched servers, Design flaws, Operating system flaws
  • Application flaws, Open services, Default passwords

Section 3: Vulnerability Assessment Types

  • Active assessment: Through network scanners
  • Passive assessment: By sniffing the traffic
  • External assessment: Vulnerabilities accessible outside the organization
  • Internal assessment: Vulnerabilities present internally
  • Host-Based assessment: Examining configuration of a specific server
  • Network assessment: Identifies potential attacks on the network
  • Application assessment: Examines configuration of web infrastructure
  • Wireless network assessment: Vulnerabilities in organization's wireless network

Section 4: Vulnerability Management

Evaluation and control of risks and vulnerabilities in the system.

Phases

  1. Pre-assessment phase: Creating baseline — identifying critical assets and prioritizing them
  2. Assessment phase: Vulnerability assessment — identifying known vulnerabilities
  3. Post-assessment phase:
    • Risk assessment: Assessing vulnerability and risk levels for identified assets
    • Remediation: Mitigating and reducing severity of identified vulnerabilities
    • Verification: Ensuring all phases completed successfully
    • Monitoring: Identifying new threats and vulnerabilities

Vulnerability Assessment Solution Types

  • Product-based: Installed in the internal network
  • Service-based: Offered by third parties
  • Tree-based assessment: Different strategies selected for each machine
  • Inference-based assessment: Find protocols → Scan services → Select vulnerabilities → Execute tests

Section 5: Vulnerability Scoring Systems

CVE — Common Vulnerabilities and Exposures

A list of common identifiers for publicly known cybersecurity vulnerabilities maintained by mitre.org.

Example: CVE-2020-0023 — disclosure of user contacts over Bluetooth due to missing permission check on Android.

CVSS — Common Vulnerability Scoring System

A free and open industry standard for assessing the severity of computer system security vulnerabilities. Helps assess and prioritize vulnerability management processes. Assigns severity scores to vulnerabilities. Score calculator depends on metrics that include ease and impact of exploit.

NVD — National Vulnerability Database

U.S. government repository of standards-based vulnerability management data at nvd.nist.gov. Includes databases of security checklist references, security-related software flaws, misconfigurations, product names, and impact metrics.

Section 6: Vulnerability Assessment Report

A written report created after an assessment is performed. Classified into security vulnerability report and security vulnerability summary.

  • Details of what has been done and discovered during the assessment
  • Helps organizations resolve security issues if they exist
  • Typically contain information about the scan, target, and results

Vulnerability Scanner Operation (3 Steps)

  1. Locate the live hosts in the network
  2. Enumerate open ports and services
  3. Test the found services for known vulnerabilities by analyzing responses

Section 7: Shellshock Vulnerability

What is Shellshock?

Also known as bashdoor or bash bug. A privilege escalation vulnerability enabling arbitrary command execution. Caused by family of security bugs in the Unix Bash shell.

Related CVE Entries

  • CVE-2014-6271, CVE-2014-6277
  • CVE-2014-6278, CVE-2014-7169
  • CVE-2014-7186, CVE-2014-7187

How It Works

Achieved by manipulating the environment variable list and then causing Bash to run. Upon startup, Bash parser executes scripts saved as environment variables.

$ env x='() { :;}; echo vulnerable' bash -c "echo this is a test"

Prints first vulnerable then this is a test.

Exploitation via CGI

To exploit, there needs to be a way to talk to Bash. Often exploits websites using CGI (Common Gateway Interface). In Apache, this is done using mod_cgi — a way to let Apache execute script files and send output to the client. Apache passes information to CGI scripts using environment variables.

"Shellshock makes Heartbleed look insignificant." — ZDNet

Impact

Thousands of attacks were reported when the bug was revealed, including botnets against the United States Department of Defense.

Detecting Shellshock with Nmap

nmap -sV -p 80 --script http-shellshock --script-args uri=/cgi-bin/blabla.sh,cmd=ls 192.168.122.17
  • -sV: Detect services and versions
  • -p: Port 80 (or -p- for entire port range)
  • --script: Test different scripts/vulnerabilities from Nmap scripts page
  • --script-args: Optional — uri and cmd arguments

Section 8: SSL/TLS Vulnerabilities

Heartbleed

Bug in OpenSSL, a widely used implementation of TLS. Introduced and patched in April 2014. Results from improper input validation (no boundary check) in TLS heartbeat extension, causing the server to send more data in memory than allowed — classified as buffer over-read.

Heartbleed Attack Flow

  • Normal: Client: "Send me 4 letter word: bird" → Server: "bird"
  • Malicious: Client: "Send me 500 letter word: bird" → Server: "bird. Server master key is... User Carol wants to change password..."

Millions of webpages were affected. Known impacts include stealing of millions of patient records and account hijacking with CEO impersonation.

Detecting Heartbleed

nmap -p 443 --script ssl-heartbleed <target>

Will return "State: NOT VULNERABLE" if not vulnerable. Also exploitable via Metasploit module openssl_heartbleed.

POODLE — Padding Oracle On Downgraded Legacy Encryption

Forcing a degradation to a vulnerable SSL/TLS version. TLS handshakes are walked down the connection until a usable/vulnerable one is found — exploits backwards compatibility. A man-in-the-middle exploit affecting both SSL and TLS.

  • POODLE attack against SSL: Takes advantage of clients' fallback to SSL 3.0. Attackers make 256 SSL 3.0 requests on average to reveal a single byte.
  • POODLE attack against TLS: Caused by some implementations not following TLS specifications. Exploits CBC encryption mode in TLS 1.0–1.2 protocols.

FREAK — Factoring RSA Export Keys

A man-in-the-middle attack forcing downgrade of RSA key to a weaker length, enabling successful brute-force attacks. Exploits cryptographic weakness in the SSL/TLS protocols.

SSL/TLS Renegotiation Vulnerability

Leads to plaintext injection attacks against SSL 3.0 and all current versions of TLS. Discovered by Marsh Ray and Steve Dispensa (November 2009). Turkish grad student Anil Kurmus exploited it to steal Twitter login credentials (November 2009).

Mitigation

Proposed standard RFC 5746 verifies previous renegotiation handshakes between client and server.

Testing

openssl s_client -connect <website>:443

Then type R for renegotiate and press ENTER.

DROWN — Decrypting RSA with Obsolete and Weakened eNcryption

Exploits modern SSL/TLS suites by exploiting their obsolete SSLv2 protocol support. The only viable countermeasure is to disable SSLv2 on all servers.

Section 9: Automated Penetration Testing Tools

Tool Overview

  • CANVAS (proprietary) — Exploit gallery and development framework
  • Core Impact (proprietary) — All-inclusive automated testing framework
  • Nmap with custom scripts — For footprinting, scanning, vulnerability analysis, and DoS attacks

Automated vs Manual Penetration Testing

Automated Testing Advantages

  • Helps initial analysis to understand where potential vulnerabilities exist
  • Enables testers to build efficient exploit strategies
  • Same pen test multiple times from different entry points
  • Reduces costs

Automated Testing Disadvantages

  • Can miss unforeseen instances
  • Usually works from "inside" of the network
  • Fails to work in complex scenarios
  • Usually does not exploit vulnerabilities
  • Not as creative as humans in social engineering

Section 10: Vulnerability Scanning Tools

Nmap

Nmap has scripting functionality written in LUA. You can scan multiple servers for multiple ports for multiple vulnerabilities.

  • -A: Enables OS detection, version detection, script scanning and traceroute
  • Can be used for footprinting, scanning, vulnerability analysis

Nessus

Proprietary port and vulnerability scanner. Scans include misconfigurations, default passwords (has Hydra built-in), DoS vulnerabilities. Can be used for compliance auditing like PCI DSS audit scans.

Burp Suite

Proxy tool to scan web vulnerabilities. Allows manual testers to intercept all requests and responses between the browser and the target application. Allows viewing, editing or dropping individual messages.

Nikto

Open source web server vulnerability scanner. Majorly looks for outdated software, dangerous files/CGI etc.

nikto -host cloudarchitecture.io

Many modern scanners including Nessus and OpenVAS use Nikto for their analysis.

Microsoft Baseline Security Analyzer (MBSA)

Identifies missing security updates and common security misconfigurations. Assesses Windows and its software (Internet Explorer, IIS web server, Microsoft SQL Server, office macro settings). Deprecated.

OpenVAS

Open-source software framework of several services and tools offering vulnerability scanning and vulnerability management.

Section 11: Metasploit Framework

What is Metasploit?

A framework for building and performing exploit attacks against targets. Modular architecture allowing code re-use instead of copying or re-implementing on a per-exploit basis. Source code | Website

Free Version Features

  • Developing and executing exploit code against remote target machines
  • Database of vulnerabilities and platform to execute different exploits
  • Fuzzing tools to discover vulnerabilities
  • Automated exploitation of known vulnerabilities (weak passwords for Telnet, SSH, HTTP)
  • Manual exploitation and brute forcing
  • Zenmap (Nmap GUI)

Paid (Pro) Version Features

  • Web application testing (OWASP Top 10)
  • Dynamic payloads for anti-virus evasion
  • Has web interface

Free alternative: Armitage — open-source GUI.

Meterpreter

Payload that provides control over an exploited target system. Runs as a DLL loaded inside any process on a target machine. Resides entirely in memory and writes nothing to disk.

msfvenom

Generates stand-alone payload. Combines payload generation and encoding to avoid antivirus detection.

msfvenom -a x86 --platform Windows -p windows/shell/bind_tcp -e x86/shikata_ga_nai -b '\x00' -f python
  • -p <payload-name>: e.g., windows/meterpreter/bind_tcp
  • -f <format>: e.g., exe or raw (shellcode)
  • -b or -e: Encoding options
  • -i <number>: Number of encoding iterations for more stealth

msfconsole — All-in-One Console

The most feature-rich and stable MSF interface. Example workflow:

  1. Run msfconsole
  2. Search for a service: search unrealirc
  3. Use exploit: use exploit/unix/irc/unreal_ircd_3281_backdoor
  4. Show and set payload: show payloads, set PAYLOAD <name>
  5. Set required options: show options, set <option-name> <value>
  6. Run exploit: exploit — hopefully you end up in a terminal session as root!

Note: Disclosure date is not the same as when vulnerability was found — it can be before but not published.
