Module 8: Sniffing Network Traffic

Section 1: Sniffing Fundamentals

Network sniffing = the practice of capturing and analyzing traffic passing through a network. Attackers use it to extract sensitive information like passwords, emails, and personal data.

Network Types

  • Broadcast networks: All devices share the same communication channel. A packet sent to one device is received by all (e.g., Ethernet hubs). Easy to sniff — all traffic flows through every port.
  • Switched networks: Switches forward packets only to the intended destination MAC address. Sniffing more difficult but possible via ARP poisoning, port mirroring, etc.

Protocol Basics

Protocols = rules and conventions for communication between devices. Each protocol has a header containing metadata (source IP, destination IP, ports, flags, etc.).

TCP Header Fields

  • Source Port: Port number of the sender
  • Destination Port: Port number of the receiver
  • Sequence Number: Tracks order of packets
  • Acknowledgment Number: Next expected sequence number
  • Flags: URG, ACK, PSH, RST, SYN, FIN — control connection state
  • Window Size: Amount of data the receiver can process

OSI Model Layers Relevant to Sniffing

  1. Physical Layer (Layer 1): Capturing raw signals
  2. Data Link Layer (Layer 2): MAC addresses, Ethernet frames, ARP
  3. Network Layer (Layer 3): IP addresses, ICMP, routing
  4. Transport Layer (Layer 4): TCP/UDP ports, session tracking
  5. Application Layer (Layer 7): HTTP, FTP, SMTP credentials and data

Section 2: Sniffing Techniques

Promiscuous Mode

Normal NIC mode: only processes packets destined for its own MAC address. Promiscuous mode: NIC captures ALL packets on the network segment, regardless of destination MAC.

Most packet capture tools (Wireshark, tcpdump) enable promiscuous mode automatically.

MAC Address Flooding

Switches maintain a CAM (Content Addressable Memory) table mapping MAC addresses to ports. When the table fills up, the switch enters fail-open mode and broadcasts all traffic like a hub.

How It Works

  1. Attacker sends大量 fake MAC addresses with random source addresses
  2. Switch CAM table fills up
  3. Switch can no longer look up destinations
  4. Switch broadcasts all traffic to all ports
  5. Attacker captures the broadcast traffic

Mitigation

  • Port security: Limit max MAC addresses per switch port
  • Sticky MAC: Dynamically learn and lock MAC addresses
  • Shutdown on violation: Disable port when limit exceeded

ARP Poisoning (ARP Spoofing)

Attacker sends forged ARP replies to associate their MAC address with the IP address of a legitimate device (e.g., default gateway). This redirects traffic through the attacker's machine.

ARP Protocol Basics

  • ARP resolves IP addresses to MAC addresses on local network
  • ARP replies are unsolicited — hosts accept them without requesting
  • ARP cache entries have no expiration by default

MITM via ARP Poisoning

  1. Attacker sends fake ARP reply to Victim: "Gateway IP is at Attacker MAC"
  2. Attacker sends fake ARP reply to Gateway: "Victim IP is at Attacker MAC"
  3. All traffic between Victim and Gateway flows through Attacker
  4. Attacker forwards traffic (undetected MITM) or modifies it

Mitigation

  • Static ARP entries: Manually map IP to MAC (not scalable)
  • ARP inspection (DAI): Dynamic ARP Inspection on switches
  • ARP monitoring tools: Detect unusual ARP activity

VLAN Hopping

Attack to sniff traffic from another VLAN by exploiting VLAN configuration.

Methods

  • Switch spoofing: Attacker's switch emulates DTP (Dynamic Trunking Protocol) to negotiate trunk with target switch, gaining access to all VLANs
  • Double tagging: Attaches two VLAN tags to a frame — first tag stripped by first switch, second tag processed by destination switch

Mitigation

  • Disable DTP on all ports
  • Set access ports explicitly
  • Use a dedicated native VLAN not used for user traffic
  • Change default VLAN ID (use VLAN 999 instead of VLAN 1)

Sticky Sessions

Attacker sends a packet to a switch with the destination MAC address of the gateway. The switch learns the attacker's MAC as the gateway's MAC in its CAM table, redirecting traffic to the attacker.

DHCP Starvation + Rogue Access Point

Attacker creates大量 DHCP DISCOVER requests to exhaust available IP addresses. Then sets up a rogue access point as the only available DHCP server, directing all victim traffic through their machine.

Section 3: Sniffing Tools

Wireshark

Most popular open-source network protocol analyzer. Captures and interactively analyzes network traffic in real-time.

Key Features

  • Deep inspection of hundreds of protocols
  • Live capture and offline analysis
  • Display filters, search, and coloring rules
  • Export data in various formats (CSV, XML, PCAP)

Basic Commands/Filters

  • http — Show only HTTP traffic
  • tcp.port == 80 — Show TCP port 80 traffic
  • ip.addr == 192.168.1.1 — Show traffic to/from IP
  • dns — Show DNS queries/responses
  • tcp.flags.syn == 1 and tcp.flags.ack == 0 — SYN packets only

Tcpdump

Command-line packet capture tool for Linux/Unix systems.

# Capture all traffic on eth0
tcpdump -i eth0

# Capture HTTP traffic
tcpdump -i eth0 port 80

# Save to file for later analysis
tcpdump -i eth0 -w capture.pcap

# Read from file
tcpdump -r capture.pcap

# Specific IP and port
tcpdump -i eth0 host 192.168.1.1 and port 443

Airodump-ng

Part of Aircrack-ng suite. Captures 802.11 wireless packets for analysis.

airodump-ng wlan0mon

Nmap

Network discovery and security auditing tool. Can perform sniffing-related tasks like ARP scanning.

nmap -sn 192.168.1.0/24  # Ping sweep
nmap -sA 192.168.1.0/24   # ARP scan

Ettercap

Comprehensive suite for MITM attacks. Supports ARP poisoning, DNS spoofing, and packet capture/sniffing.

# ARP poisoning on subnet
ettercap -T -q -i eth0 -M arp:remote // //

# Sniff only
ettercap -T -M arp /192.168.1.1// /192.168.1.254//

Dsniff

Collection of tools for network auditing. Includes:

  • dsniff: Captures passwords automatically
  • arpspoof: Sends forged ARP replies
  • dnsspoof: Spoofs DNS responses
  • macof: Floods switch CAM table

Cain & Abel

Windows password recovery tool with built-in sniffer. Supports ARP poisoning, RIP, VRRP, OSPF, STP, and NetFlow sniffing.

X-Force Sniffer

IBM X-Force network sniffer for capturing and analyzing network traffic.

Mirai Source Code

Contains network scanning and enumeration code used by the Mirai botnet for reconnaissance.

Section 4: Protocol Analysis

TCP Three-Way Handshake

  1. SYN: Client sends SYN to server
  2. SYN-ACK: Server responds with SYN-ACK
  3. ACK: Client sends ACK — connection established

HTTP (Unencrypted)

Transmits data in plaintext. Easily sniffed for usernames, passwords, cookies, and sensitive data.

Common Ports:

  • HTTP: Port 80
  • HTTPS: Port 443

FTP (Unencrypted)

Transfers files in plaintext. Credentials and file contents can be captured.

Common Ports:

  • Control: Port 21
  • Data: Port 20

SMTP (Unencrypted)

Sends email in plaintext. Can be sniffed for email content and credentials.

Common Ports:

  • SMTP: Port 25
  • SMTP with TLS: Port 587

POP3/IMAP (Unencrypted)

Email retrieval protocols that transmit credentials and email content in plaintext.

Common Ports:

  • POP3: Port 110
  • IMAP: Port 143

DNS

Domain Name System queries are typically unencrypted. Attackers can sniff to discover domain names, internal hostnames, and potentially extract data via DNS tunneling.

Common Ports:

  • DNS: Port 53 (UDP/TCP)

Credentialed Protocols Often Sniffed

Encrypted Protocols (Harder to Sniff)

  • SSH (Port 22): Encrypted channel
  • HTTPS (Port 443): TLS/SSL encrypted
  • SFTP (Port 22): FTP over SSH
  • IPsec: Network-layer encryption

Section 5: Sniffing Countermeasures

Cryptographic Protocols

Use encrypted protocols instead of plaintext alternatives:

  • HTTPS instead of HTTP
  • SSH instead of Telnet/Rlogin
  • SFTP/SCP instead of FTP
  • TLS/SSL for email (STARTTLS)
  • DNS over HTTPS (DoH) / DNS over TLS (DoT): Encrypted DNS

Network-Level Defenses

  • Switched networks: Use switches instead of hubs
  • Port security: Limit MAC addresses per port, shutdown on violation
  • Dynamic ARP Inspection (DAI): Validate ARP packets
  • DHCP Snooping: Filter untrusted DHCP messages
  • Encrypted traffic analysis: Use tools to detect anomalies in encrypted traffic
  • VLAN segmentation: Isolate sensitive traffic
  • Disable unused switch ports: Prevent unauthorized access

Intrusion Detection/Prevention

  • IDS/IPS: Detect ARP poisoning, unusual traffic patterns
  • Network-based IDS (NIDS): Monitor network traffic for suspicious activity
  • Host-based IDS (HIDS): Monitor for promiscuous mode on hosts

Physical Security

  • Secure network equipment in locked rooms
  • Avoid wireless networks when possible
  • Use fiber optic cables (harder to tap than copper)

Monitoring and Detection

  • Monitor for unusual ARP activity
  • Check for hosts in promiscuous mode
  • Monitor CAM table size changes
  • Use network behavior analysis tools

Tools for Detection

  • Arpwatch: Monitors ARP traffic and alerts on changes
  • Wireshark: Detect unusual network patterns
  • Snort/Suricata: IDS for detecting sniffing-related attacks

Section 6: Wireless Sniffing

802.11 Frame Types

  • Management frames: Association, authentication, beacon
  • Control frames: ACK, CTS, RTS, RTS
  • Data frames: Carries application data

Wireless Sniffing Tools

  • Aircrack-ng suite: airodump-ng, aireplay-ng, aircrack-ng
  • Kismet: Wireless network detector, sniffer, and IDS
  • Wireshark: Can capture 802.11 with monitor mode

Monitor Mode

Similar to promiscuous mode for wireless. Allows NIC to capture all 802.11 traffic in the air, not just traffic destined for its MAC address.

airmon-ng start wlan0  # Enable monitor mode on wlan0

Rogue Access Points

Unauthorized APs connected to a secure network. Attackers use them to sniff or redirect traffic.

Types

  • Wireless rogue AP: Connected directly to wired network
  • Evil twin: Fake AP with legitimate-sounding SSID

Countermeasures

  • Use WPA3 encryption
  • Implement 802.1X authentication (RADIUS)
  • Regularly scan for rogue APs
  • Disable SSID broadcasting
  • Use network segmentation
