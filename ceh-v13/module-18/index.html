CEH v13 Module 18: Lateral Movement

Lateral movement is the set of techniques attackers use to move through a network from an initial compromise to other systems. This module covers pass-the-hash (PtH), pass-the-ticket (PTT), remote service exploitation (SMB, RDP, SSH, WinRM), pivoting techniques, credential dumping, and Metasploit post-exploitation modules.

Key Topics Covered

  • Pass-the-Hash (PtH): using NTLM hashes instead of passwords
  • Pass-the-Ticket (PTT): using stolen Kerberos tickets
  • Remote service attacks: SMB, RDP, SSH, WinRM, WMI
  • Pivoting: using compromised host as jump point
  • Credential dumping: Mimikatz, LSASS extraction
  • Lateral movement detection and prevention
  • Metasploit post-exploitation modules

Important Terms & Concepts

Pass-the-Hash (PtH): Attacker captures NTLM hash and uses it to authenticate to remote services without knowing the plaintext password. Tools: Mimikatz, Impacket (psexec.py, smbexec.py).
Pass-the-Ticket (PTT): Attacker extracts Kerberos TGT (ticket-granting ticket) and uses it to authenticate without credentials. More advanced than PtH — works in pure Kerberos environments.
Pivoting: Using a compromised host as a jump point to reach otherwise inaccessible internal networks. Tools: Metasploit port forwards, ssh -L/-D, Chisel, Ligolo.
Mimikatz: Most widely known credential dumping tool. Extracts passwords, hashes, PINs, and Kerberos tickets from memory. Can perform PtH and PTT attacks.
Credential Dumping: Extracting credentials from memory (LSASS on Windows). Methods: lsass.exe injection, token manipulation, registry extraction of cached credentials.
WinRM (Windows Remote Management): Microsoft's implementation of WS-Management protocol. Commonly abused for lateral movement via PowerShell Invoke-Command and Impacket's winrm.py.

How to Study This Module

  • Understand the difference between PtH and PTT attacks
  • Know which remote services are commonly abused for lateral movement
  • Learn pivoting techniques and tools
  • Understand how credential dumping works and detection methods

Frequently Asked Questions

What is lateral movement?
The process attackers use to move through a network from an initial compromise to other systems, escalating privileges and expanding access.

How do you prevent lateral movement?
Network segmentation, least privilege access, disable SMB/RDP where possible, LSA protection, Credential Guard, MFA, endpoint detection (EDR), and monitoring for anomalous authentication patterns.

What is Lateral Movement in Ethical Hacking?

Lateral Movement is a critical phase in the post-exploitation stage of an intrusion, and a dedicated topic on the Certified Ethical Hacker v13 (CEH v13) exam. After an attacker gains initial access to a system (via phishing, web exploitation, or vulnerability exploitation), they must traverse the internal network to reach high-value targets: domain controllers, databases, executive workstations, and sensitive file servers. Lateral movement exploits the trust relationships inherent in enterprise networks — if your credentials (or their hashes/tickets) are valid on one machine, they're likely valid on many more. On the CEH v13 exam, questions related to Module 18 account for approximately 7% of total questions.

Key Concepts in Lateral Movement

  • Pass-the-Hash (PtH) & NTLM Vulnerability: The NTLM protocol fundamentally trusts the hash as proof of knowledge. When a client authenticates to a server, it proves possession of the NTLM hash (NTOWFv1 = MD4 of UTF-16LE password) — not the plaintext password itself. This means anyone who can capture the hash can authenticate as that user without ever knowing the password. On the CEH exam, know the attack flow: (1) Dump NTLM hashes from LSASS memory using Mimikatz (sekurlsa::logonpasswords) or by reading SAM database on disk; (2) Use the hash to authenticate to remote services via SMB (psexec.py, smbexec.py), WMI (wmiexec.py), or WinRM (winrm.py from Impacket). PtH is particularly dangerous in domain environments because a Domain Admin's NTLM hash grants access to every system in the domain. Mitigation: Enable LSA Protection (prevents unauthorized remote read of lsass.exe memory), enable Credential Guard (isolates authentication secrets in VSM enclave), and disable NTLM where Kerberos suffices. On the CEH exam, the key distinction: PtH works without plaintext password but requires NTLM to be enabled; it fails in pure Kerberos environments.
  • Pass-the-Ticket (PTT) & Kerberos Ticket Stealing: In Active Directory, Kerberos authentication uses tickets: TGT (Ticket-Granting Ticket, obtained from KDC after initial AS-REQ/AS-REP exchange) and TGS (Ticket-Granting Service, obtained using TGT to access specific services). PTT attacks involve extracting a valid TGT from LSASS memory and replaying it to request service tickets for any domain service. This grants domain-wide access equivalent to Domain Admin privileges if the TGT belongs to an admin account. On the CEH exam, know that: (1) TGTs are AES-encrypted with the user's NT hash as key — so PTT effectively requires knowledge of the NT hash; (2) Ticket lifetime matters — default TGT lifetime is 10 hours, after which the ticket expires; (3) Rubeus tool (by Andy Robbins) provides more advanced Kerberos attacks: AS-REP roasting (for accounts without pre-authentication), golden ticket forging (using krbtgt account's NT hash to create valid TGTs for any user forever); (4) PTT is harder to detect than PtH because Kerberos logs look similar for legitimate and stolen tickets. Mitigation: Enable Credential Guard, monitor for service ticket requests from unusual source IPs, and implement tiered administration model (no Domain Admins logging onto workstations).
  • Pivoting Techniques & Network Tunneling: Pivoting is used when the initial compromised host has network access to internal subnets that are unreachable from the attacker's external position. The compromised host becomes a proxy/jump box. Common techniques: (1) SSH tunneling — ssh -L (local port forward), ssh -D (dynamic SOCKS proxy); (2) Metasploit port forwarding — route add, portfwd add for TCP/UDP forwarding through the compromised host; (3) Chisel — lightweight TCP/UDP tunneling over HTTP(S), harder to detect than raw SSH; (4) Ligolo-ng — modern tunneling framework supporting multi-hop chaining and DNS tunneling; (5) SOCKS5 proxy via compromised host — tools like ProxyChains allow routing all attacker traffic through the pivot. On the CEH exam, know that pivoting is legal in authorized penetration tests but illegal without written scope authorization. The key concept: you don't need direct network reachability to a target if you have a foothold on a machine that can reach it. Detection: monitoring for proxy-like behavior (one internal IP making many distinct connection requests to different internal IPs), unusual outbound connections from workstation to workstation, and DNS tunneling patterns.
  • Credential Dumping & LSASS Memory Extraction: Credential dumping is the prerequisite for PtH/PTT attacks — without extracted credentials, you can't move laterally. On Windows, the primary target is LSASS (Local Security Authority Subsystem Service) which holds authentication secrets in memory: plaintext passwords, NTLM hashes, Kerberos tickets, and PINs. Methods: (1) Read process memory of lsass.exe using OpenProcess/ReadProcessMemory API (requires SeDebugPrivilege — typically requires SYSTEM or admin on target); (2) Inject DLL into LSASS that calls LsaFetchCredentials; (3) Create minidump of LSASS and analyze offline with tools like Mimikatz or Hashdump; (4) Registry extraction — read SAM hive from disk for local account hashes (requires SYSTEM access to C:\Windows\System32\config\SAM); (5) DPAPI-based extraction for browser-saved passwords and Windows Credential Manager. On the CEH exam, know that modern EDR solutions detect LSASS memory access attempts (Process Injection, ReadProcessMemory to lsass.exe PID), and that Credential Guard specifically prevents this by running authentication in an isolated VSM enclave that cannot be read even by SYSTEM.

Tools Used in Lateral Movement

Lateral movement tools referenced on the CEH exam include Mimikatz (the definitive credential dumping and lateral movement tool: logonpasswords extracts all credentials from LSASS, sekurlsa::pth performs pass-the-hash, kerberos::ptt performs pass-the-ticket, and kerberos::golden forges golden tickets; operates on Windows systems and is detected by virtually all EDR solutions), Impacket (Python-based suite of network protocol tools: psexec.py for remote code execution via SMB named pipes, wmiexec.py for WMI-based lateral movement, smbexec.py for service creation over SMB, atexec.py for Task Scheduler abuse, and secretsdump.py for remote credential extraction without touching target disk), Metasploit (post-exploitation framework with modules for: multi/recon/local_exploit_suggester to find local privilege escalation paths, post/windows/manage/migrate to pivot through compromised hosts, route/portfwd for network tunneling, and credentials module for managing harvested credentials), Cobalt Strike (commercial red team tool with beacon-based C2 architecture supporting: built-in lateral movement modules, Malleable C2 profiles for evasion, socks proxy for pivoting, and integrated credential dumping via process injection); Rubeus (Kerberos-specific attack tool by Andy Robbins: asreproast for AS-REP roasting, golden/silver ticket forging, PTT execution, and S4U2Self/S4U2Proxy impersonation attacks); and Ligolo-ng (modern tunneling framework supporting multi-hop chains, HTTP/HTTPS proxy modes, and DNS tunneling for low-noise pivoting). On the CEH exam, know that Impacket is the most commonly referenced tool for PtH attacks in study materials, while Mimikatz is associated with credential dumping.

How to Study Lateral Movement for the CEH v13 Exam

To effectively study Module 18 for the Certified Ethical Hacker exam:

  1. Create a comparison table: Attack Type (PtH vs PTT vs Golden Ticket) | What's Stolen (NTLM hash / TGT / krbtgt hash) | Protocol Required (NTLM / Kerberos / Kerberos) | Scope (single system / domain-wide / domain-wide perpetual) | Tool Used (Mimikatz pth / Rubeus ptt / Mimikatz golden) | Detection Method (SMB auth anomaly / ticket reuse / impossible ticket lifetime). The exam frequently asks you to identify which attack is being described based on its mechanism
  2. Hands-on exercise in a lab environment: Set up a two-VM Active Directory lab (DC + workstation using VirtualBox or GNS3). On the workstation: run Mimikatz logonpasswords as admin to dump NTLM hashes, then use psexec.py from a Kali VM to connect to the DC using the harvested hash. Document each step and the exact commands used. This directly mirrors exam questions about the PtH workflow. For PTT: capture a TGT with Rubeus dump /credentialtype:tgt and use Rubeus ptt to inject it
  3. Memorize the defense-in-depth mitigations for lateral movement: (1) LSA Protection (LocalSecurityAuthority\RestrictRemoteSAM registry key) — blocks remote access to lsass.exe; (2) Credential Guard (VBS-protected) — isolates secrets in VSM enclave; (3) Tiered Administration Model (T0=Domain Controllers, T1=member servers, T2=workstations) — prevents admin credentials from being present on all tiers; (4) Network segmentation with firewall rules restricting workstation-to-workstation SMB (445); (5) EDR with LSASS memory access alerts and behavioral detection of unusual authentication patterns
  4. Review related modules: Module 5 (System Hacking) for the initial compromise techniques that give you the foothold needed for lateral movement, and Module 19 (Post-Exploitation & IR) for what happens after lateral movement reaches the objective — data exfiltration, C2 establishment, and the incident response team's detection and containment procedures

Frequently Asked Questions About Lateral Movement

What is a golden ticket attack and how does it differ from Pass-the-Ticket?

A golden ticket attack forges a Kerberos TGT from scratch using the krbtgt account's NTLM hash, whereas Pass-the-Ticket uses a legitimately issued TGT that was stolen from memory. Golden Ticket: The attacker first dumps the krbtgt account's NT hash (typically via DCSync attack or LSASS access on a Domain Controller), then uses Mimikatz (kerberos::golden /user:Administrator /rc4:krbtgt_hash) to forge a TGT for any user in the domain. The forged ticket is valid until the krbtgt password is changed (or forever if never changed). This grants persistent, domain-wide access that survives logoff, password changes, and even service restarts. On the CEH exam, know that: (1) Golden tickets require the krbtgt hash — you must already have Domain Admin level access to obtain it; (2) Detection is difficult because the ticket looks cryptographically valid — the KDC cannot distinguish forged from legitimate; (3) Mitigation: rotate the krbtgt password twice (first rotation invalidates existing golden tickets, second ensures consistency), monitor for TGTs with impossible encryption types or lifetime values, and enable Kerberos pre-authentication on all accounts. The key difference from PTT: PTT is ephemeral (ticket expires per normal policy) while golden ticket is persistent until krbtgt rotation.

How does LSA Protection prevent lateral movement attacks?

LSA Protection (also called LSASS protection) is a Windows feature that restricts which processes can access the memory of the LSASS (Local Security Authority Subsystem Service) process. It's configured via the registry key: HKLM\SYSTEM\CurrentControlSet\Control\Lsa\RestrictRemoteSAM with values 0 (default — any authenticated user), 1 (only LocalSystem and services), or 2 (only LocalSystem). When enabled at level 1+, it prevents remote access to LSASS memory from other machines, blocking attacks like: (1) Remote process injection into lsass.exe; (2) ReadProcessMemory calls from remote contexts; (3) Network-based credential dumping. On the CEH exam, know that LSA Protection is a defense-in-depth measure that works alongside Credential Guard and EDR. It does NOT prevent local LSASS access by a process already running on the same machine with SYSTEM privileges — for that, Credential Guard (VBS-based isolation) is required. Together, LSA Protection + Credential Guard + EDR detection create a layered defense against the most common lateral movement prerequisites (credential dumping). The practical implication: in a well-protected environment, an attacker cannot easily obtain NTLM hashes from memory and must resort to more advanced techniques like DCSync (requiring existing domain admin) or offline attacks.

Module 5 provides the "in" while Module 18 provides the "through." The transition from initial compromise to lateral movement typically involves privilege escalation to at minimum domain user level before PtH/PTT attacks become viable
  • Module 19: Post-Exploitation & Incident Response — After successful lateral movement, the attacker reaches their objective (data exfiltration, ransomware deployment, C2 establishment). Module 19 covers what defenders must do to detect and respond: SIEM alert correlation for authentication anomalies, IR playbooks for containing lateral movement (isolate affected systems, reset compromised credentials including krbtgt), and forensic evidence collection (memory dumps from LSASS, network PCAPs showing C2 beacons, authentication logs showing the attack path). On the CEH exam, know that the blue team's primary defense against lateral movement is detection speed — isolating a compromised host before it can pivot to the domain controller dramatically limits the attacker's impact
