CEH v13 Module 3: Scanning Networks

This module covers active network scanning techniques used to discover live hosts, open ports, and services on a target network. You will learn nmap scan types, port scanning methods, vulnerability scanning, banner grabbing, and techniques for bypassing IDS and firewalls.

Important Terms & Concepts

TCP SYN scan (-sS): Half-open scan — sends SYN packets and analyzes responses without completing the TCP handshake. Most common stealth scan.
TCP connect() scan (-sT): Completes the full TCP three-way handshake. More reliable but easier to detect than SYN scan.
FIN scan (-sF): Sends a FIN packet — non-listening ports respond with RST. Can bypass some firewalls.
Xmas Tree scan (-sX): Sets FIN, PSH, and URG flags like a Christmas tree. Named for the combination of flags set.
Ping scan (-sP): ICMP ping sweep to discover live hosts on a network range.
Version detection (-sV): Probes open ports to determine service and version information beyond just port status.
Idlescan (-sI): Zombie-based stealthy port scan that uses a third-party system to avoid sending packets from your own IP.
FTP Bounce attack (-b): Uses a proxy FTP server to scan a target through the relay, hiding the true source.

nmap Timing Options

  • -T0 Paranoid (300s wait) — IDS evasion
  • -T1 Sneaky (15s wait) — slow and stealthy
  • -T2 Polite (0.4s wait) — reduces network congestion
  • -T3 Normal — default timing
  • -T4 Aggressive (300s timeout, 1.25s per probe)
  • -T5 Insane (75s timeout, 0.3s per probe) — fastest

Frequently Asked Questions

Which nmap scan is most commonly used?
SYN scan (-sS) is the most popular because it is fast, widely available (requires root), and stealthy since it does not complete the TCP handshake.

What is the difference between a vulnerability assessment and port scanning?
Port scanning identifies open ports and services. Vulnerability assessment goes further by identifying known CVEs and weaknesses in those services.

What is Scanning Networks in Ethical Hacking?

Scanning Networks is a core domain of the Certified Ethical Hacker v13 (CEH v13) exam administered by EC-Council. This module covers active network scanning techniques for discovering live hosts, open ports, running services, and vulnerabilities on target systems. The primary tool — Nmap — provides dozens of scan types from half-open SYN scans to UDP sweeps, each with different trade-offs between speed, accuracy, and stealth. Understanding packet-level mechanics of each scan type is essential because the CEH exam frequently asks scenario-based questions about which scan to use in a given situation. On the CEH v13 exam, questions related to Module 3 account for approximately 8% of total questions.

Key Concepts in Scanning Networks

  • TCP Three-Way Handshake & Half-Open Scanning: The foundation of all TCP scans. A full handshake (SYN → SYN-ACK → ACK) identifies open ports but is easily logged. Half-open SYN scanning sends only the initial SYN and reads the response — SYN-ACK means open, RST means closed — without ever completing the connection. This is why -sS is both faster and stealthier than -sT.
  • Stealth Scan Variants (FIN, Xmas, NULL): These scans exploit a gap in older TCP/IP implementations where filtered firewalls only check for SYN packets. A FIN scan (-sF) sends a packet with only the FIN flag set; if no response comes, the port is likely filtered. Xmas (-sX) sets FIN, PSH, and URG flags; NULL sends no flags at all. Modern operating systems respond with RST to all closed ports regardless of flags, but these techniques can still bypass poorly configured stateless firewalls.
  • Nmap Timing & Performance Options: The -T0 through -T5 timing templates control how aggressively Nmap sends packets and waits for responses. -T3 is the default; -T4 is recommended for most engagements with modern networks; -T5 is fastest but may trigger IDS alerts. Understanding when to use slower settings (paranoid/sneaky) versus faster ones is a common exam question type.
  • Vulnerability Scanning vs Port Scanning: Port scanning identifies which ports are open and what services run on them. Vulnerability scanning (Nessus, OpenVAS, Qualys) goes further by matching running services against databases of known CVEs to identify specific exploitable weaknesses. The CEH exam distinguishes these two activities and expects you to know which tools perform each function.

Common Exam Mistakes in Module 3

Believing a SYN scan completes the connection: -sS is half-open by design — the scanner sends a SYN, reads the reply (SYN-ACK means open, RST means closed), then tears down with RST. Because no session is ever established, many logs record nothing, which is exactly why it is called stealth scanning.
Reading silence as "closed": A port that answers RST is closed; a port that answers nothing may simply be filtered by a firewall. OPEN, CLOSED and FILTERED are distinct exam answers on packet-trace questions, and Nmap reports OPEN|FILTERED when it cannot decide between the two.
Picking a TCP scan for UDP services: SYN and Connect scans only see TCP, so DNS, DHCP and SNMP need -sU with ICMP port-unreachable analysis. Separately, when the question is "is this firewall stateful or stateless," the exam answer is an ACK scan (-sA), not a version-detection run.

Tools Used in Network Scanning

Scanners the CEH exam references for this domain, by job:

  • Nmap: the industry-standard scanner — SYN/Connect/FIN/Xmas/NULL/Idle flags, OS detection from TCP/IP stack fingerprints, and ping-sweep host discovery with -sn
  • NSE (Nmap Scripting Engine): Lua-based scripts that extend Nmap beyond port status into service interrogation and quick vulnerability checks
  • Masscan: internet-scale port scanning at extreme speed — the exam's answer for mapping a huge address space quickly
  • ZMap: stateless high-speed scanner in the same bulk-discovery category as Masscan
  • Angry IP Scanner / Advanced IP Scanner / Superscan: GUI ping-sweep utilities for finding live hosts on a LAN before detailed scanning; PingPlotter adds continuous path monitoring
  • Netcat (nc): swiss-army socket tool used for banner grabbing — connect straight to an open port and read the service banner
  • Nessus (Tenable): the commercial vulnerability scanner that takes port-scan results and matches services against CVE databases
  • OpenVAS (Greenbone): the open-source counterpart to Nessus, commonly paired with it in exam questions about scanning tool families

Worked Example: Reading a Scan Result Line by Line

You run nmap -sS against an authorized test host and read three results: port 443 replies SYN-ACK, port 80 replies RST, and port 53 gives no response at all.

Translation and follow-up: 443 is open with a service running, 80 is closed because the host is reachable but nothing listens, and 53 is filtered — the probe was dropped, so you cannot conclude it is closed. Re-probe with -sU to check UDP DNS properly, add -O to fingerprint the OS from initial TTL, window size and TCP option ordering, then hand the confirmed open ports to a vulnerability scanner such as Nessus.

Frequently Asked Questions About Scanning Networks

Why is a SYN scan called a half-open scan?

A SYN scan is called "half-open" because it only completes the first step of the TCP three-way handshake. The scanner sends a SYN packet and receives either a SYN-ACK (port open) or RST (port closed), but never sends the final ACK to complete the connection. Because the full connection is never established, many target systems do not log the attempt — making it stealthier than a connect() scan. However, it requires raw socket access (root/administrator privileges), which is why it cannot be run in non-privileged mode.

What is the difference between a filtered and a closed port?

A closed port actively rejects the connection — it sends back a RST (reset) packet, indicating no service is listening there. A filtered port provides no response at all — a firewall is silently dropping the packets before they reach the target. On the CEH exam, this distinction matters: a closed port means the host is up and the service is stopped, while a filtered port means a firewall or security device is blocking access. The Nmap output explicitly labels ports as "open," "closed," or "filtered" based on these different responses.
