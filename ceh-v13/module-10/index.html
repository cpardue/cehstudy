CEH v13 Module 10: Denial-of-Service

Denial-of-Service (DoS) attacks aim to make a system or network unavailable to legitimate users by overwhelming resources. This module covers DoS vs DDoS attacks, SYN flood, Smurf attack, Ping of Death, Teardrop, buffer overflow attacks, application layer DoS, botnet-based distributed attacks, and mitigation techniques.

Key Topics Covered

  • DoS vs DDoS: single-source vs distributed attacks
  • SYN flood attack: overwhelming TCP connection tables with half-open connections
  • Smurf attack: ICMP amplification using broadcast addresses
  • Ping of Death: oversized or fragmented ICMP packets crashing systems
  • Teardrop attack: overlapping IP fragments causing system crash
  • Buffer overflow attacks on network services
  • Application layer DoS (Layer 7): HTTP flood, Slowloris, RUDY
  • Distributed Denial-of-Service (DDoS) via botnets
  • DoS mitigation and prevention strategies

Important Terms & Concepts

DoS (Denial-of-Service): An attack from a single source that overwhelms a target's resources, making it unavailable to legitimate users.
DDoS (Distributed Denial-of-Service): A DoS attack launched from multiple sources (typically a botnet), making it harder to mitigate through simple IP blocking.
SYN Flood: Attacker sends rapid TCP SYN requests but never completes the handshake. Target's connection table fills with half-open connections, exhausting resources.
Smurf Attack: ICMP-based amplification attack. Attacker sends ping (ICMP echo) to a broadcast address with spoofed source IP (victim). All hosts on the network reply to the victim simultaneously.
Ping of Death: Sends malformed or oversized ICMP packets (>65,535 bytes) that overflow buffers when reassembled, causing system crashes.
Teardrop: Sends IP fragments with overlapping offset values. When the target tries to reassemble them, the system crashes due to the malformed fragment data.
Botnet: A network of infected computers (zombies) controlled by a command-and-control (C2) server. Used to launch massive DDoS attacks from thousands of sources simultaneously.

How to Study This Module

  • Understand the difference between DoS and DDoS attacks
  • Memorize each attack type and its specific mechanism (SYN flood, Smurf, Ping of Death, Teardrop)
  • Know mitigation techniques: SYN cookies, rate limiting, traffic filtering, blackholing
  • Understand how botnets enable distributed attacks at massive scale

Frequently Asked Questions

What is the difference between DoS and DDoS?
DoS comes from one source. DDoS comes from many sources simultaneously (a botnet), making it much harder to mitigate since you can't simply block one IP address.

What is a SYN flood attack?
The attacker sends thousands of TCP SYN packets but never responds with the final ACK. The target's TCP connection table fills up with half-open connections, preventing new legitimate connections.

What are Denial-of-Service Attacks in Ethical Hacking?

Denial-of-Service (DoS) and Distributed Denial-of-Service (DDoS) attacks are a critical domain on the Certified Ethical Hacker v13 (CEH v13) exam administered by EC-Council. This module covers attacks that target availability — one of the three pillars of the CIA triad (Confidentiality, Integrity, Availability). DoS attacks range from simple volumetric floods to sophisticated amplification attacks that can bring down entire internet infrastructure. The CEH v13 exam emphasizes understanding attack classification by OSI layer (volumetric at L3/L4 vs protocol exploitation vs application-layer at L7) and the specific mechanism each attack uses to exhaust target resources. On the CEH v13 exam, questions related to Module 10 account for approximately 10% of total questions.

Key Concepts in Denial-of-Service Attacks

  • Volumetric vs Protocol vs Application DoS: The CEH exam categorizes DoS by how they exhaust resources: Volumetric attacks (SYN flood, UDP flood, ICMP flood) consume bandwidth and connection table space at L3/L4; Protocol attacks (Teardrop, Ping of Death) exploit implementation flaws in stack processing to cause crashes; Application-layer attacks (Slowloris, HTTP flood, R.U.D.Y.) target L7 services by consuming application resources (threads, connections, CPU for processing). On the exam, identify the attack type from the description: if it mentions 'half-open connections' = SYN flood, 'broadcast address with spoofed source' = Smurf/amplification, 'open but incomplete HTTP requests' = Slowloris.
  • Amplification & Reflection Attacks: The most effective modern DDoS technique. The attacker sends small requests to open servers (DNS, NTP, Memcached, SSDP) with a spoofed source IP (victim). The server responds to the victim with a response much larger than the original request. Amplification factors: DNS ~54x, NTP monlist ~556x, Memcached ~51,000x, SSDP ~30x. On the CEH exam, know that amplification requires: (a) open/accessible service on internet-facing servers, (b) source IP spoofing capability, (c) a protocol where response is disproportionately larger than request. The 2016 Dyn attack and 2017 Mirai botnet attacks are real-world examples the exam may reference.
  • Layer 7 DoS (Slowloris & HTTP Flood): Slowloris opens many TCP connections to a web server but sends only partial HTTP headers, keeping each connection open and consuming worker threads without completing requests. The server exhausts its thread pool while each connection appears legitimate. HTTP flood (different from volumetric) sends valid but resource-intensive HTTP GET/POST requests at high rates, consuming CPU/memory for processing rather than bandwidth. R.U.D.Y. (R-U-Dead-Yet) is a Slowloris variant that slowly trickles POST body data to keep connections alive. On the CEH exam, distinguish: SYN flood = L4 TCP handshake exhaustion; Slowloris = L7 thread pool exhaustion with incomplete requests; HTTP flood = L7 resource exhaustion with complete but numerous requests.
  • DDoS Mitigation Strategy: The CEH exam tests layered defense approaches: (1) BCP38/BCP84 — source address validation at network edge to prevent spoofing (prerequisite for amplification defense); (2) SYN cookies — allow connections without reserving table space until handshake completes; (3) Rate limiting — cap requests per IP on specific endpoints; (4) AnyCast routing — distribute traffic across global PoPs so no single point is overwhelmed; (5) DDoS scrubbing (CDN services like Cloudflare, Akamai) — filter attack traffic before it reaches origin; (6) Blackholing/Null routing — drop all traffic to attacked IP as last resort. On the exam, know that no single technique mitigates all DDoS types — defense must be layered by attack vector.

Tools Used in DoS/DOS Attacks

DoS tools referenced on the CEH exam include HOIC (High Orbit Ion Cannon) and LOIC (Low Orbit Ion Cannon) (graphical/CLI tools for HTTP/UDP flood attacks — LOIC uses simple TCP/UDP/HTTP flood, HOIC supports more protocol options), Slowloris (Python-based Layer 7 attack tool that opens incomplete HTTP connections to exhaust web server threads), hping3 (powerful packet generation tool supporting SYN flood, UDP flood, ping of death, teardrop — `hping3 -S --flood` for SYN flood), and Mirai source code (real-world botnet malware that was leaked publicly — demonstrates IoT DDoS at scale with UDP amplification). For monitoring and detection: ntopng (traffic analysis), Zeek/Bro (network security monitoring identifying anomaly patterns), and cloud-based DDoS dashboards. On the CEH exam, know that hping3 is the most versatile single tool for demonstrating L3/L4 DoS techniques in a lab environment.

Frequently Asked Questions About DoS Attacks

What is the difference between a SYN flood and an HTTP flood on the CEH exam?

SYN flood operates at Layer 4 (Transport): the attacker sends TCP SYN packets but never completes the three-way handshake with an ACK. The target's kernel maintains half-open connection entries in a limited-size table, and once full, it cannot accept new legitimate connections. Mitigation: SYN cookies (assign stateless identifier instead of reserving table space). HTTP flood operates at Layer 7 (Application): the attacker sends complete, valid HTTP GET or POST requests at high volume. Each request is processed by the web application — consuming CPU for business logic, database queries, template rendering. The connections are fully established and legitimate-looking. Mitigation: rate limiting per IP/endpoint, CDN-based challenge mechanisms, request fingerprinting to identify bot patterns. On the CEH exam, the key distinction is: SYN flood = connection table exhaustion at kernel level; HTTP flood = application resource exhaustion at process level.

Why are IoT devices so effective in DDoS attacks?

IoT devices (webcams, IP cameras, smart TVs, routers) make ideal DDoS zombies because: (1) they run on Linux with default/weak credentials that are never changed, (2) they have persistent network connectivity (always on), (3) they have limited processing power so they don't run security software, (4) many have exposed UPnP/SSDP services that enable amplification, and (5) their firmware rarely receives security patches. The Mirai botnet (2016) demonstrated this by compromising ~600,000 IoT devices in its first 20 hours, launching a 1 Tbps DDoS against Dyn DNS that took down Twitter, Netflix, GitHub, and many other major services. On the CEH exam, know that IoT DDoS is a growing threat because the attack surface expands with every connected device, and the primary defense is network-level filtering (blocking unauthorized outbound UDP) rather than endpoint security which doesn't exist on these devices.
