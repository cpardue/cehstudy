CEH v13 Module 5: Vulnerability Analysis

Vulnerability analysis is the process of identifying, quantifying, and prioritizing vulnerabilities in systems and applications. This module covers vulnerability assessment methodologies, scanning tools like Nessus and OpenVAS, CVE/CVSS frameworks, patch management, and risk assessment strategies.

Key Topics Covered

  • Vulnerability assessment vs. penetration testing vs. security audit
  • CVE (Common Vulnerabilities and Exposures) database
  • CVSS (Common Vulnerability Scoring System) metrics
  • Vulnerability scanning tools: Nessus, OpenVAS, Nexpose, Qualys
  • Network-based vs. host-based vulnerability scanners
  • Patch management and remediation strategies
  • Risk assessment and prioritization frameworks
  • Compliance scanning and regulatory requirements

Important Terms & Concepts

Vulnerability Assessment: The process of identifying, quantifying, and prioritizing vulnerabilities using automated tools and manual analysis to understand an organization's security posture.
CVE (Common Vulnerabilities and Exposures): A standardized dictionary of publicly disclosed security vulnerabilities. Each CVE has a unique identifier (e.g., CVE-2024-1234).
CVSS (Common Vulnerability Scoring System): A framework for scoring vulnerability severity from 0.0 to 10.0. Scores: 0.0-3.9 (Low), 4.0-6.9 (Medium), 7.0-8.9 (High), 9.0-10.0 (Critical).
Nessus: One of the most widely used vulnerability scanning tools by Tenable. Provides comprehensive scanning for networks, web apps, databases, and cloud environments.
OpenVAS: An open-source vulnerability scanner that provides full-featured vulnerability detection and reporting capabilities.
False positive: When a scanner reports a vulnerability that does not actually exist. A major challenge in vulnerability management.
False negative: When a scanner fails to detect a vulnerability that does exist. More dangerous than false positives as it creates false confidence.

CVSS Score Categories

  • 0.0 – 3.9 — Low severity (green)
  • 4.0 – 6.9 — Medium severity (yellow/orange)
  • 7.0 – 8.9 — High severity (red)
  • 9.0 – 10.0 — Critical severity (dark red)

What is Vulnerability Analysis in Ethical Hacking?

Vulnerability Analysis is a core domain of the Certified Ethical Hacker v13 (CEH v13) exam administered by EC-Council. This module covers the systematic process of identifying, quantifying, and prioritizing security weaknesses in systems before they can be exploited by attackers. Unlike scanning (which finds open ports) or enumeration (which extracts data), vulnerability analysis matches discovered services and configurations against known vulnerability databases to identify specific CVEs that could be weaponized. The CVSS scoring framework provides a standardized way to rank vulnerabilities by severity, enabling organizations to prioritize remediation. On the CEH v13 exam, questions related to Module 5 account for approximately 10% of total questions.

Key Concepts in Vulnerability Analysis

  • CVE and CVSS Frameworks: The Common Vulnerabilities and Exposures (CVE) database assigns unique identifiers to publicly disclosed vulnerabilities (e.g., CVE-2024-1234). The Common Vulnerability Scoring System (CVSS) provides a numerical severity score from 0.0 to 10.0 based on attack vector, complexity, privileges required, user interaction, scope, and impact on confidentiality/integrity/availability. CVSS v3.1 is the current standard. The CEH exam frequently tests CVSS metric calculations and severity classification thresholds.
  • Network-Based vs Host-Based Scanning: Network-based vulnerability scanners (Nessus, OpenVAS) scan from a remote position to identify issues visible from the network — misconfigurations, outdated services, missing patches. Host-based scanners (Qualys Agent, CIS CAT) install on individual endpoints and perform deep analysis including registry checks, file integrity, local service configurations, and compliance posture. The CEH exam distinguishes these approaches and expects you to know when each is appropriate.
  • Patch Management & Remediation: Vulnerability analysis is only useful if findings are remediated. Patch management involves testing patches in staging, deploying to production on a schedule aligned with risk priority (critical first), and verifying fixes. Understanding the SLA framework for patching (e.g., critical within 7 days, high within 30 days) and how to handle legacy systems that cannot be patched are common exam scenarios.
  • Risk Assessment & Prioritization: Raw vulnerability lists can contain thousands of findings. Risk assessment applies context — asset criticality, exploitability (is there public exploit code?), compensating controls (WAF, IDS) — to produce a prioritized remediation plan. The CEH exam tests the concept that a 9.8 CVSS score on a segmented internal system with no public exploit may be lower priority than a 7.2 score on an internet-facing web server with active exploitation in the wild.

Tools Used in Vulnerability Analysis

The primary vulnerability scanning tools tested on the CEH exam include Nessus (Tenable) — the industry-standard commercial scanner with a free home-use version, OpenVAS/Greenbone Community Edition — the leading open-source alternative, QualysGuard — cloud-based continuous monitoring, and Nexpose (Rapid7) — focused on risk-based prioritization. For supplementary scanning, Nikto tests web servers for known misconfigurations, while the Nmap Scripting Engine (NSE) with vuln category scripts performs quick vulnerability checks. Hands-on practice involves running Nessus against a Metasploitable VM to generate real vulnerability reports, then interpreting CVSS scores and determining remediation priority. The CEH exam expects familiarity with scanner output interpretation rather than specific button-level knowledge.

How to Study Vulnerability Analysis for the CEH v13 Exam

To effectively study Module 5 for the Certified Ethical Hacker exam:

  1. Memorize CVSS score ranges: 0.0–3.9 Low, 4.0–6.9 Medium, 7.0–8.9 High, 9.0–10.0 Critical — and understand each CVSS metric (AV, AC, PR, UI, S, C, I, A)
  2. Understand the difference between vulnerability assessment (identifying), penetration testing (exploiting), and security auditing (compliance) — the CEH exam tests these distinctions in scenario questions
  3. Hands-on exercise: Download Nessus Essentials (free), scan a Metasploitable 2 VM, and produce a report. Identify at least 5 vulnerabilities, look up their CVE IDs, and calculate or verify their CVSS scores. Write a one-paragraph remediation recommendation for each.
  4. Review related modules: Module 4 (Enumeration) for how service identification feeds vulnerability scanning, and Module 6 (System Hacking) for how identified vulnerabilities are actively exploited

Frequently Asked Questions About Vulnerability Analysis

What is the difference between vulnerability assessment and penetration testing?

Vulnerability assessment is a broad, automated process that identifies and lists potential security weaknesses across an environment without attempting to exploit them. Penetration testing goes further by actively exploiting identified vulnerabilities to demonstrate real-world impact — proving that an attacker could actually access sensitive data or escalate privileges. On the CEH exam, know that VA answers "what are the gaps?" while PT answers "how badly can they be exploited?" and "what would an attacker actually gain?" Both require written authorization, but PT typically requires a more detailed scope document and rules of engagement.

How does CVSS scoring work on the CEH exam?

CVSS v3.1 assigns a base score (0.0–10.0) calculated from eight metrics: Attack Vector (Network/Adjacent/Local/Physical), Attack Complexity (Low/High), Privileges Required (None/Low/High), User Interaction (None/Required), Scope (Unchanged/Changed), and impact on Confidentiality, Integrity, and Availability (None/Low/High). The CEH exam typically provides a vulnerability description and asks you to determine the correct CVSS score or severity category. Key exam tip: a vulnerability that requires no user interaction, no privileges, is remotely exploitable over the network with high impact on all three CIA dimensions will always score 9.0 or above (Critical).
