CEH v13 Module 8: Sniffing

Sniffing is the act of intercepting and analyzing traffic on a network. This module covers passive vs active sniffing, packet capture tools like Wireshark and tcpdump, ARP poisoning attacks, MAC address table overflow, DHCP starvation, and techniques for evading switched networks.

Key Topics Covered

  • Passive vs active sniffing techniques
  • Packet capture tools: Wireshark, tcpdump, Cain & Abel, EtherPeek
  • ARP poisoning/ARP spoofing attacks
  • MAC address table overflow (CAM table flooding)
  • DHCP starvation attacks
  • Switched network evasion techniques
  • Protocol analysis and payload extraction
  • Network monitoring countermeasures

Important Terms & Concepts

Passive Sniffing: Simply listening to network traffic without sending packets. Works on hubs where all traffic is broadcast to every port. Cannot work on switches without additional attacks.
Active Sniffing: Injecting packets into the network to redirect traffic toward the attacker. Includes ARP poisoning, MAC flooding, and DHCP starvation attacks.
ARP Poisoning (ARP Spoofing): Sending fake ARP replies to associate the attacker's MAC address with the target's IP. Creates a Man-in-the-Middle position.
CAM Table Overflow: Flooding a switch's MAC address table until it enters "fail-open" mode, broadcasting all traffic like a hub. Tools: Macof, Cain & Abel.
DHCP Starvation: Creating fake DHCP requests with random MACs to exhaust the DHCP pool (DHCP exhaustion). Also called a DHCP starvation attack. Tools: Yersinia.
Wireshark: The world's most popular network protocol analyzer. GUI-based, supports hundreds of protocols, captures and displays packet-level data in real-time.
tcpdump: Command-line packet capture tool for Linux/Unix. Uses BPF (Berkeley Packet Filter) syntax for filtering captured packets.

How to Study This Module

  • Understand the difference between passive and active sniffing with examples
  • Know how ARP poisoning creates a Man-in-the-Middle position
  • Memorize how MAC flooding forces switches into hub-like behavior
  • Practice using Wireshark to analyze captured traffic

Frequently Asked Questions

What is the difference between hub and switch sniffing?
On a hub, all traffic goes to every port — passive sniffing works easily. On a switch, traffic is sent only to the destination MAC, so active attacks (ARP poisoning, MAC flooding) are required.

How does ARP poisoning work?
The attacker sends unsolicited fake ARP replies telling the gateway that the attacker's MAC is the target's IP. All traffic for the target now goes through the attacker's machine.

What is Network Sniffing and Traffic Analysis in Ethical Hacking?

Network Sniffing and Traffic Analysis is a core domain of the Certified Ethical Hacker v13 (CEH v13) exam administered by EC-Council. This module covers both the offensive techniques for intercepting network traffic (ARP poisoning, MAC flooding, DHCP starvation) and the defensive skill of analyzing captured packets to identify threats, extract credentials, and understand protocol behavior. The CEH v13 exam emphasizes understanding Layer 2 attacks on switched networks, as modern environments eliminated the simple hub-based sniffing that was once trivial. On the CEH v13 exam, questions related to Module 8 account for approximately 10% of total questions.

Key Concepts in Sniffing and Traffic Analysis

  • ARP Poisoning & Man-in-the-Middle: The ARP protocol has no authentication mechanism — any host can claim to be any IP address. An attacker sends forged ARP replies associating their MAC with the gateway's IP (or the target's IP), intercepting all traffic through their machine. Tools like Ettercap automate this with built-in MiTM capabilities including HTTP injection, credential capture, and SSL stripping. The CEH exam tests understanding of how ARP cache tables work and why they make this attack possible on any flat LAN segment.
  • CAM Table Flooding (MAC Overflow): Switches maintain a MAC address table (CAM table) mapping MAC addresses to ports. When flooded with millions of fake MAC addresses, the table overflows and the switch enters "fail-open" mode — forwarding all frames to all ports like a hub. Tools: Macof (Kali), Cain & Abel. On the CEH exam, know that this is a temporary DoS that enables sniffing only while flooding continues. Defense: port security with maximum MAC limit per port.
  • DHCP Starvation Attack: The attacker floods the network with DHCP Discover requests using randomized MAC addresses, exhausting the DHCP server's address pool. Once the pool is exhausted, the attacker can run their own rogue DHCP server, becoming the gateway for all new clients — enabling both sniffing and man-in-the-middle attacks. Tools: Yersinia, DHCPig. On the CEH exam, distinguish this from simple DoS (the goal is traffic redirection, not just denial of service). Defense: DHCP snooping on managed switches.
  • Credential Extraction from Traffic: Many protocols transmit credentials in cleartext or with weak protection: HTTP Basic Auth (base64-encoded = trivially decoded), FTP (cleartext username/password), Telnet (cleartext), SMTP/POP3 without STARTTLS, and legacy SMB (NTLM hashes). Wireshark's "Follow TCP Stream" feature reconstructs entire conversations. On the CEH exam, know which protocols are inherently insecure and which require additional encryption to protect credentials.

Tools Used in Sniffing and Traffic Analysis

Essential sniffing tools for CEH exam preparation include Wireshark (GUI packet analyzer supporting 500+ protocols with BPF/Wireshark display filters), tcpdump (command-line equivalent using BPF syntax — `tcpdump -i eth0 port 80`), Ettercap (automated ARP poisoning and MiTM framework with plugin architecture), Cain & Abel (Windows-based: password recovery, network monitoring, protocol analysis), and Yersinia (multi-protocol attack tool supporting DHCP, OSPF, VTP attacks). For analysis specifically, understanding Wireshark display filters is exam-critical: `ip.addr == 192.168.1.1`, `http.request.method == GET`, `tcp.flags.syn == 1`. Hands-on practice: capture your own network traffic in VirtualBox with a host-only adapter, identify at least 5 cleartext protocols, and document the specific filter expressions used to isolate them.

How to Study Sniffing for the CEH v13 Exam

To effectively study Module 8 for the Certified Ethical Hacker exam:

  1. Memorize the three main switched network attacks and their specific goals: ARP poisoning (redirect traffic), MAC flooding (force broadcast mode), DHCP starvation (become gateway) — the CEH exam presents scenarios asking which attack is being described
  2. Learn Wireshark display filter syntax: know how to filter by IP, port, protocol, HTTP method, and TCP flags — practical questions may ask you to identify the correct filter for a given scenario
  3. Hands-on exercise: Set up a VirtualBox network with two VMs (attacker + victim) using a host-only adapter. Install Kali on attacker, Windows on victim. Perform ARP poisoning with Ettercap, capture HTTP login credentials in Wireshark, and document the complete attack chain from initiation to credential capture
  4. Review related modules: Module 11 (Session Hijacking) for how sniffed session tokens are exploited, and Module 6 (System Hacking) for how captured credentials enable lateral movement

Frequently Asked Questions About Sniffing and Traffic Analysis

How does ARP poisoning create a Man-in-the-Middle position?

ARP works on the principle that any host can send an unsolicited ARP reply claiming "IP X has MAC Y." The attacker sends two forged replies: (1) to the victim saying "the gateway's IP is now MY MAC" and (2) to the gateway saying "the victim's IP is now MY MAC." Both devices update their ARP caches and route traffic through the attacker. All traffic between victim and gateway now passes through the attacker's machine, which can pass it along (transparent MiTM) or modify it. On the CEH exam, know that ARP poisoning works because: (a) ARP has no authentication, (b) hosts accept unsolicited ARP replies without verification, and (c) the ARP cache is updated immediately without timeout waiting for the previous entry to expire.

What defensive measures prevent network sniffing on a LAN?

The primary defenses against LAN sniffing attacks are: (1) **Port Security** — limit the number of MAC addresses per switch port, disabling the port on violation; (2) **Dynamic ARP Inspection (DAI)** — validates ARP packets against a DHCP snooping binding table, dropping spoofed replies; (3) **DHCP Snooping** — builds a trusted binding table of IP-MAC associations from legitimate DHCP exchanges, blocking rogue DHCP servers; (4) **802.1X Port-Based Authentication** — requires device authentication before network access, limiting exposure to authorized devices only; (5) **Network Segmentation (VLANs)** — limits broadcast domain size so a single attacker cannot see traffic across the entire network; (6) **Encryption (HTTPS, TLS)** — even if traffic is intercepted, encrypted payloads are unreadable. On the CEH exam, know that no single defense is sufficient — defense in depth requires multiple layers.
