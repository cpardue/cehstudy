CEH v13 Module 12: Evading IDS, Firewalls & Honeypots

This module covers techniques used to bypass network security controls. Attackers use evasion methods to avoid detection by IDS/IPS systems, firewall rules, and honeypots. Understanding these techniques is essential for both offensive security testing and defensive deployment.

Key Topics Covered

  • IDS vs IPS: detection vs prevention systems
  • Network-based (NIDS) vs host-based (HIDS) intrusion detection
  • Signature-based vs anomaly-based detection methods
  • Firewall evasion: fragmentation, tunneling, IP spoofing
  • Honeypot and honeynet types and detection
  • IPsec evasion techniques

Important Terms & Concepts

IDS (Intrusion Detection System): Monitors network traffic for suspicious activity and generates alerts. Does not block traffic — purely detection.
IPS (Intrusion Prevention System): Like IDS but actively blocks or drops malicious traffic in real-time. Can cause false positives that disrupt legitimate traffic.
NIDS (Network IDS): Monitors all traffic across the entire network at strategic points. Placed at the perimeter or on VLANs.
HIDS (Host IDS): Monitors activity on a single host — file integrity, system logs, running processes, registry changes.
Signature-Based Detection: Matches traffic against a database of known attack patterns. Misses zero-day attacks but has low false-positive rate.
Anomaly-Based Detection: Establishes a baseline of normal traffic and alerts on deviations. Detects unknown attacks but has higher false-positive rate.
Fragmentation Attack: Sending packet fragments that reassemble into an attack payload outside the IPS inspection window. Defeats signature-based IDS/IPS.
Honeypot: A decoy system designed to attract attackers and study their behavior. Low-interaction (simulated services) vs high-interaction (real systems).

How to Study This Module

  • Differentiate IDS from IPS — detection vs prevention
  • Know NIDS vs HIDS and signature-based vs anomaly-based detection
  • Memorize evasion techniques: fragmentation, tunneling, spoofing, IP address rotation
  • Understand honeypot types and how to detect them during penetration testing

Frequently Asked Questions

What is the difference between IDS and IPS?
IDS only monitors and alerts on suspicious activity. IPS actively blocks or drops malicious traffic in real-time. Both are important but IPS can cause false positives.

How do you evade a firewall during scanning?
Techniques include IP fragmentation, using DNS tunneling (port 53), encrypting traffic, slow scanning rates, decoy scanning (using multiple source IPs), and splitting payloads across fragments.

What is IDS and Firewall Evasion in Ethical Hacking?

Evading Intrusion Detection Systems (IDS), Intrusion Prevention Systems (IPS), firewalls, and honeypots is a critical offensive security skill tested on the Certified Ethical Hacker v13 (CEH v13) exam administered by EC-Council. This module covers the full range of evasion techniques that penetration testers and attackers use to operate without triggering alerts or being blocked by defensive controls. Understanding these techniques from the attacker's perspective is essential for defenders who need to tune their security controls to detect them. On the CEH v13 exam, questions related to Module 12 account for approximately 10% of total questions.

Key Concepts in Evading IDS, Firewalls & Honeypots

  • Signature-Based Evasion (Fragmentation & Encoding): Signature-based IDS/IPS systems match packet content against known attack patterns. The primary evasion is IP fragmentation: splitting an attack payload across two or more fragments so that the signature pattern spans a fragment boundary and no single fragment matches the database entry. Example: a classic SQL injection signature looks for "UNION SELECT" — if the attacker sends "UNION" in fragment 1 and "SELECT" in fragment 2, a shallow-parsing IDS sees neither match. Encoding variations (URL encoding, hex, null byte insertion) also defeat exact-string matching. On the CEH exam, know that modern IDS with deep packet inspection (DPI) reassemble fragments before signature matching, making simple fragmentation less effective against properly configured systems — but it remains a tested concept.
  • Protocol Tunneling & Allowlist Bypass: When a firewall only permits specific ports (e.g., DNS port 53, HTTPS port 443, ICMP), attackers tunnel their traffic through these allowed channels. DNS tunneling encodes command-and-control data in DNS query names (subdomain labels) and responses (text records). ICMP tunneling carries data in the payload of ping packets. SSH tunneling creates encrypted channels over port 22. The firewall sees only allowed-protocol traffic and passes it through. On the CEH exam, distinguish: fragmentation defeats signature matching at L3/L4; tunneling defeats port-based filtering by using the allowed port for different purposes. Both require the defender to implement deep protocol inspection, not just port/protocol filtering.
  • Honeypot Detection & Response: A honeypot is a decoy system that mimics a legitimate target to attract and study attackers. Low-interaction honeypots simulate services (fake banners, limited commands) and are detected by noticing inconsistencies (too-perfect responses, no real OS artifacts, response timing patterns). High-interaction honeypots run real operating systems with modified configurations. On the CEH exam, know that encountering a honeypot during a penetration test means: (1) stop interacting to avoid legal liability, (2) document what was observed, (3) report to the client. The ethical distinction: interacting with a honeypot without authorization may constitute unauthorized access even if it's a decoy — it is still a real system receiving your traffic.
  • NIDS vs HIDS Evasion Differences: NIDS (Network IDS) monitors traffic at network layer points (span ports, TAPs) and can be evaded by encryption (SSL/TLS) or tunneling since it only sees packets on the wire. HIDS (Host IDS) monitors activity directly on the endpoint — file system changes, process creation, registry modifications, log entries. HIDS is much harder to evade because the attacker must already have access to the host before they can blind the monitoring agent. On the CEH exam, know that NIDS sees what's on the network (bypassable with encryption); HIDS sees what's happening on the system (much harder to bypass without root/admin privileges). A comprehensive defense uses both layers — what NIDS misses, HIDS may catch.

Tools Used in IDS/IPS Evasion

Evasion tools referenced on the CEH exam include hping3 (crafts custom packets with specific flags for testing IPS response — supports fragmented packets, IP spoofing, and protocol manipulation; `hping3 -f` for fraggle attacks, `-a` for IP spoofing), Nmap (multiple evasion scan options: `-f` for fragmentation, `--mtu` to set custom MTU, `-D RND:10` for decoy scanning with 10 random IPs, `--data-length` to add random padding to packets making them look like normal traffic), crt.sh and dns2tcp/dns2tcp-ng (DNS tunneling tools that encode data in DNS queries for exfiltration over port 53), iodine (DNS-over-IPv6 tunnel creating a TCP/IP tunnel through DNS), and SpySat/honeypot detection scripts (automated checks to identify honeypot behavior patterns). For defensive testing: Suricata/Snort (open-source IDS/IPS used to verify that evasion techniques are being detected — update rule sets to test coverage). On the CEH exam, know that Nmap's `-f` (fragment) and `-D` (decoy) flags are the most commonly referenced evasion options for firewall bypass scenarios.

How to Study IDS Evasion for the CEH v13 Exam

To effectively study Module 12 for the Certified Ethical Hacker exam:

  1. Create a matrix: Evasion Technique | Defeats Which Control | Why It Works | Modern Countermeasure. The exam asks you to match techniques to the specific control they bypass and explain the mechanism — e.g., "fragmentation defeats signature-based IDS because the pattern spans a fragment boundary that the IDS does not reassemble"
  2. Memorize the distinction between what NIDS sees vs HIDS sees: NIDS = network packets (bypassable with encryption/tunneling); HIDS = host processes and files (requires root access to blind). The exam frequently asks which layer a specific technique defeats
  3. Hands-on exercise: In a VirtualBox lab, set up a Suricata IDS on a span port between an attacker VM and target VM. Run Nmap scans with increasing evasion options (`-f`, `--data-length 200`, `-D RND:5`) and observe in Suricata logs which scans generate alerts and which pass silently. Document the exact Nmap flag that causes detection to fail — this directly maps to exam questions
  4. Review related modules: Module 3 (Scanning Networks) for the scanning techniques that need evasion, and Module 10 (DoS Attacks) for how DoS traffic is shaped to avoid rate-based detection triggers

Frequently Asked Questions About IDS and Firewall Evasion

What is the difference between evading an IDS and evading a firewall on the CEH exam?

Evading an IDS means making your traffic undetectable by monitoring systems — the goal is to pass through without triggering alerts while maintaining connectivity. Techniques include fragmentation (defeating signature matching), rate normalization (staying below anomaly thresholds), encryption (hiding content from NIDS), and protocol tunneling (using allowed protocols). Evading a firewall means making your traffic pass through access control rules that would normally block it — the goal is to establish a connection that the firewall permits. Techniques include IP spoofing (appearing as an allowed source), DNS/ICMP tunneling (using allowed ports for different purposes), slow scanning (below rate limits), and exploiting misconfigured rules. On the CEH exam, the key distinction: IDS evasion = avoid detection (traffic may be blocked but you want to not be seen); Firewall evasion = gain access (you want traffic to pass through a control that would normally stop it). Both can use similar techniques but the objective differs.

Why is anomaly-based IDS harder to evade than signature-based IDS?

Signature-based IDS knows specific attack patterns and matches traffic against them — evasion is straightforward by altering the payload (fragmentation, encoding, slight modification). Anomaly-based IDS establishes a statistical baseline of normal behavior (protocol mix, packet size distributions, connection rates, timing patterns, geographic patterns) and alerts when traffic deviates. To evade anomaly detection, the attacker must make their malicious traffic statistically indistinguishable from normal traffic — matching typical packet sizes, using common protocols at normal rates, operating during expected hours, and following the same session patterns as legitimate users. This is significantly harder because there's no specific signature to avoid — you must blend in completely. On the CEH exam, know that anomaly-based IDS catches zero-day and novel attacks that signature-based systems miss, but produces more false positives (normal traffic that looks unusual). The practical implication: well-maintained security operations use both detection methods for complementary coverage.
