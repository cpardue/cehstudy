CEH v13 Module 19: Post-Exploitation & Incident Response

This module covers what happens after initial compromise — both from the attacker's perspective (persistence, privilege escalation, log clearing, data exfiltration) and the defender's perspective (incident response lifecycle, forensic investigation, recovery procedures). Understanding both sides is critical for ethical hackers.

Key Topics Covered

  • Persistence mechanisms: registry keys, scheduled tasks, services, startup folders
  • Privilege escalation: local exploits, misconfigurations, token manipulation
  • Log clearing and anti-forensics techniques
  • Data exfiltration methods and covert channels
  • Incident Response lifecycle (NIST/SANS frameworks)
  • Digital forensics fundamentals and chain of custody
  • System recovery and hardening after compromise

Important Terms & Concepts

Persistence: Maintaining access after reboot or credential changes. Methods: registry Run keys, Windows Services, scheduled tasks, WMI event subscriptions, bootkits/rootkits.
Privilege Escalation: Moving from standard user to administrator/root. Vertical escalation (higher privileges) vs horizontal escalation (different user). Tools: Mimikatz, WinPEAS, LinPEAS.
Log Clearing: Deleting or modifying event logs, firewall logs, and application logs to cover tracks. Windows: `wevtutil`, `Clear-EventLog`. Linux: `auditctl -C`, log rotation.
Data Exfiltration: Transferring stolen data out of the network. Methods: DNS tunneling, HTTP/S POST, FTP, cloud storage upload, email, ICMP tunneling, covert channels.
Incident Response Lifecycle (NIST): 1) Preparation → 2) Detection & Analysis → 3) Containment & Eradication → 4) Recovery → 5) Post-Incident Activity.
Chain of Custody: Documented record of evidence handling from collection to presentation. Critical for legal admissibility. Includes who collected, when, where, and how evidence was stored/transferred.

How to Study This Module

  • Memorize the Incident Response lifecycle phases and key activities in each
  • Know common persistence mechanisms on Windows and Linux
  • Understand privilege escalation techniques (local exploits, misconfigurations)
  • Learn anti-forensics methods and how to detect them

Frequently Asked Questions

What is the first step in incident response?
Preparation — having tools, policies, and trained personnel ready before an incident occurs. Once an incident happens, Detection & Analysis is the first active phase.

How do ethical hackers use this knowledge?
To test persistence mechanisms, verify privilege escalation paths, check if logs are properly configured, and assess incident response readiness through red team exercises.

What is Post-Exploitation and Incident Response in Ethical Hacking?

Post-Exploitation & Incident Response (Module 19) is a dual-perspective domain on the Certified Ethical Hacker v13 (CEH v13) exam. The post-exploitation side covers what an attacker does after gaining access: establishing persistence to maintain long-term access, escalating privileges to reach administrative control, covering their tracks through anti-forensics, and exfiltrating stolen data from the environment. The incident response side covers how defenders detect, contain, and recover from such attacks using structured frameworks (NIST SP 800-61, SANS PICERL). Understanding both perspectives is what makes a CEH-certified professional valuable — you must know how attackers operate to build effective defenses. On the CEH v13 exam, questions related to Module 19 account for approximately 8% of total questions.

Key Concepts in Post-Exploitation & IR

  • Persistence Mechanisms — Maintaining Access: Persistence ensures the attacker's access survives reboots, credential resets, and even system reimages. The CEH exam tests knowledge of these specific techniques: (1) Registry Run keys — HKLM\Software\Microsoft\Windows\CurrentVersion\Run (executes at user logon); (2) Windows Services — creating a new service pointing to malicious binary (sc.exe create / sc.exe start); (3) Scheduled Tasks — task scheduler entries that run at specific times or trigger conditions; (4) WMI Event Subscriptions — persistent triggers in the WMI repository that execute code when specific events occur (e.g., process start, user logon); (5) Bootkits/Rootkits — firmware-level persistence that survives OS reinstallation (UEFI bootkits like LoJax); (6) Linux persistence — .bashrc/.profile modifications, cron jobs, systemd units, PAM backdoors. On the CEH exam, know that WMI event subscriptions are among the most stealthy persistence mechanisms because they leave minimal filesystem artifacts and can trigger on legitimate system events. Detection: review scheduled tasks, services with unusual paths or startup types, WMI event filters, and compare running processes against known-good baselines.
  • Privilege Escalation — Local Exploitation Path: Privilege escalation moves from initial access (typically standard user) to administrative/root control. The CEH exam covers: (1) Kernel exploits — CVE-based exploits that escalate via kernel vulnerabilities (e.g., CVE-2021-34527 PrintSpoofer on Windows, dirty pipe/dirty cred on Linux); (2) Misconfiguration abuse — services with write permissions allowing binary replacement, unquoted service paths, token manipulation; (3) Credential harvesting for local use — stored credentials in registry, password files, service accounts running at high privilege; (4) Token/impersonation attacks — duplicating a token of a higher-privileged process (Mimikatz privilege::debug + token::steal); (5) SUID/SGID binary exploitation on Linux — finding binaries with setuid bit that can be exploited for root. Tools: WinPEAS (Windows Privilege Escalation Awesome Script — automated enumeration of all escalation paths), LinPEAS (Linux equivalent), Metasploit's local_exploit_suggester module. On the CEH exam, know that WinPEAS/LinPEAS are enumeration tools (they identify potential paths) rather than exploitation tools — you still need to apply the appropriate exploit after identification.
  • Anti-Forensics & Log Clearing: Attackers use anti-forensics to prevent defenders from understanding what happened. Techniques tested on CEH: (1) Windows Event Log clearing — wevtutil cl Security / Clear-EventLog Security (this action itself generates a log event: Event ID 1102 "The audit log was cleared"); (2) Linux log manipulation — /var/log/auth.log deletion, auditctl -C (flush audit buffers), modifying /etc/wtmp and /etc/btmp (login records); (3) Timestamp manipulation — modifying file metadata to appear recently created (touch command on Linux, PowerShell on Windows); (4) Timestomping — setting file creation/modification times to match legitimate activity; (5) Memory clearing — zeroing RAM before shutdown to prevent memory forensics. On the CEH exam, know that log clearing is self-detecting in well-configured environments: if logs are forwarded to a central SIEM before clearing, the deletion attempt is captured. The key detection signal: Event ID 1102 (log cleared) combined with Event ID 4688 (process creation showing wevtutil or cmd.exe running clear commands). Best defense: ship logs to immutable storage (SIEM, cloud WORM storage) so they cannot be modified at the source.
  • Data Exfiltration & Covert Channels: Data exfiltration is the final step where stolen data leaves the compromised environment. Methods tested on CEH: (1) DNS tunneling — encoding data into DNS query names (e.g., base32-encoded data as subdomain labels) — bypasses many egress firewalls because DNS (port 53) is rarely filtered; tools: dnscat, iodine; (2) HTTP/S POST — uploading to attacker-controlled server via web requests — most common method in real attacks; (3) Covert channels — hiding data in protocol fields that aren't normally inspected (ICMP payload, TCP timestamp field, DNS TXT records); (4) Cloud storage — uploading to public services (pastebin, cloud storage, image hosting) to avoid pattern-based detection; (5) Email exfiltration — sending data via email to attacker-controlled mailbox, often in compressed/encrypted attachments. On the CEH exam, know that DNS tunneling is the most commonly tested covert channel because it exploits the assumption that DNS traffic is trusted infrastructure. Detection: monitoring for unusually high DNS query volume from a single host, abnormally long subdomain labels (suggesting encoded data), and DNS queries to domains with high entropy (random-looking names). Network egress filtering should block direct outbound DNS to public resolvers from internal hosts (force use of internal recursive DNS with logging).

Tools Used in Post-Exploitation & IR

Post-exploitation and incident response tools referenced on the CEH exam include Mimikatz (post-exploitation Swiss army knife: privilege::debug for token manipulation, token::steal for impersonation, lsadump::sam/lsadump::dcsync for offline credential extraction, and sekurlsa module for live memory dumping), WinPEAS/LinPEAS (automated local privilege escalation enumeration scripts: WinPEAS checks for kernel exploits applicable to current OS version, unquoted service paths, weak file permissions, stored credentials in registry/services/IIS config; LinPEAS checks SUID binaries, sudo misconfigurations, writable /etc/passwd, kernel CVE applicability), Cobalt Strike (post-exploitation framework: built-in persistence modules for services/tasks/WMI, privilege escalation modules calling Windows API directly, data exfiltration via beacon's malleable profiles, and report generation for pentest deliverables), Autoruns (Sysinternals) (Microsoft's definitive persistence enumeration tool — shows ALL auto-starting programs, services, drivers, scheduled tasks, WMI subscriptions, browser extensions, and other persistence locations in a single view; used by both attackers to verify their implants and defenders to detect unauthorized persistence), Autopsy (open-source digital forensics platform for examining disk images: file system analysis, keyword search, email recovery, web history extraction, and artifact correlation), and FTK (Forensic Toolkit) (commercial forensic examination tool used in legal investigations — evidence ingestion, timeline analysis, network flow reconstruction, and report generation for court presentation). On the CEH exam, know that Autoruns is the primary tool associated with persistence detection while Autopsy is associated with digital forensics on disk images.

How to Study Post-Exploitation & IR for the CEH v13 Exam

To effectively study Module 19 for the Certified Ethical Hacker exam:

  1. Create a persistence comparison table: Mechanism | Location (registry path/file path) | Trigger (logon/reboot/scheduled/event) | Survives Reboot? | Survives Credential Reset? | Detection Method. The exam frequently asks which persistence mechanism survives specific remediation actions — e.g., "Which mechanism survives a password reset?" (Answer: services pointing to files, WMI subscriptions, bootkits — NOT registry Run keys if the user profile is reset, NOT scheduled tasks for that specific user)
  2. Hands-on exercise: On a Windows VM, use WinPEAS to enumerate privilege escalation paths. Document what it finds: applicable kernel exploits, service misconfigurations, and credential storage locations. Then use Autoruns to catalog all persistence locations. For the IR side: practice writing an incident report using the NIST framework structure — describe a simulated breach through each phase (Preparation: what should have been in place; Detection: what alerts fired; Containment: what systems were isolated; Recovery: what was rebuilt; Post-Incident: what was learned)
  3. Memorize the NIST SP 800-61r2 phases and key activities: Preparation (IR plan, tools, training, communication) → Detection & Analysis (identify, triage, collect evidence) → Containment/Eradication/Recovery (short-term isolation, remove root cause, restore from clean media) → Post-Incident (lessons learned report, update IR plan). Know that the SANS model (PICERL) separates Identification from Preparation and adds Lessons Learned as a distinct final phase. The exam may ask you to identify which phase a given activity belongs to
  4. Review related modules: Module 5 (System Hacking) for the initial access techniques that lead to post-exploitation activities, and Module 18 (Lateral Movement) for how persistence and privilege escalation enable network-wide movement. On the CEH exam, know the complete attack lifecycle: Reconnaissance → Initial Access (Module 5) → Privilege Escalation (Module 19) → Lateral Movement (Module 18) → Objectives (Exfiltration/Ransomware from Module 19) → Cover Tracks (Anti-forensics from Module 19)

Frequently Asked Questions About Post-Exploitation & IR

What is a WMI event subscription and why is it significant for persistence detection?

A WMI (Windows Management Instrumentation) event subscription is a persistent trigger that executes code when a specific system event occurs, without creating a file on disk or appearing in standard process monitoring. The attacker uses the WMIC command or PowerShell to create three components: (1) An Event Filter — defines what triggers execution (e.g., __TimerFilter for periodic execution, __EventFilter for process start); (2) A Consumer — defines what executes (CommandLineEventConsumer running a binary, or ActiveScriptEventConsumer running code); (3) A Binding — connects the filter to the consumer. Example: wmic /namespace:\\root\\subscription create __EventFilter name="f" QueryLanguage="WQL" Query="SELECT * FROM __TimerFilter WITHIN 60". On the CEH exam, know that WMI event subscriptions are significant because: (1) They leave minimal filesystem artifacts (no dropped executable needed if using existing binaries like cmd.exe or powershell.exe); (2) They persist across reboots automatically; (3) They are not visible in standard Task Manager or Services.msc — you must specifically query WMI repository (Get-WmiObject -Namespace root/subscription) or use Autoruns' "WMI" tab. Detection: enumerate all event filters, consumers, and bindings in WMI subscription namespace and compare against a known-good baseline. The practical implication: if a defender only checks services and registry Run keys for persistence, they will miss WMI-based implants entirely.

What is chain of custody and why is it critical in digital forensics?

Chain of custody is the documented, unbroken record of who handled digital evidence from the moment it was collected until it is presented in court (or used in an investigation). It includes: (1) Date/time of collection; (2) Name and credentials of collector; (3) Location where evidence was found; (4) Description of evidence (make, model, serial number, IP address, hash value); (5) Each transfer — who received it, when, why, and how it was stored/transferred; (6) Storage conditions (forensic write-blocker used? Evidence bag sealed? Hash verified at each transfer?); (7) Final disposition. On the CEH exam, know that chain of custody is critical because: (1) Legal admissibility — without proper chain of custody, evidence can be excluded from court proceedings; (2) Integrity verification — hash values (MD5/SHA-256) calculated at collection and verified at each transfer prove the evidence was not modified; (3) Accountability — every person who touched the evidence is documented, preventing tampering. The standard process: photograph evidence in situ → connect through write-blocker → create forensic image (dd, FTK Imager, or X-Ways) → calculate hash of original and image → seal original in anti-static bag with evidence label → store in evidence locker with restricted access. On the CEH exam, know that the forensic write-blocker is the single most important piece of equipment — it prevents any modification to the original media during imaging, which is what makes the copy admissible as a true representation of the original.

Related CEH v13 Modules

  • Module 5: System Hacking — Post-exploitation (Module 19) is the natural continuation of initial compromise in Module 5. After exploiting a vulnerability to gain code execution on a target system, the attacker's immediate next steps are: establish persistence (so access survives reboot), escalate privileges (to reach admin/root), and then either exfiltrate data or use the system for further attacks. Module 19 covers all three of these post-compromise activities. On the CEH exam, know that the transition from initial compromise to post-exploitation is where the penetration test's real value lies — finding a single exploit is less important than understanding what an attacker could do with it
  • Module 18: Lateral Movement — Post-exploitation (Module 19) and Lateral Movement (Module 18) overlap significantly in practice. Persistence mechanisms established in Module 19 (services, scheduled tasks, WMI subscriptions) on one host enable the lateral movement techniques of Module 18 (PtH, PTT, pivoting) to other hosts. Privilege escalation in Module 19 is often the prerequisite for lateral movement — you typically need at least domain user level (and often admin) before PtH/PTT attacks become effective. On the CEH exam, know that these two modules represent a continuous phase of the attack lifecycle: escalate locally (M19) → move laterally (M18) → escalate on new host (M19) → repeat until objective reached
