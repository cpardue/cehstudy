CEH v13 Module 7: Malware Threats

This module covers the various types of malicious software used by attackers, including viruses, worms, trojans, ransomware, spyware, rootkits, fileless malware, and polymorphic threats. Understanding these threats is critical for both offensive and defensive security professionals.

Key Topics Covered

  • Virus vs worm differences: file infection vs self-replication across networks
  • Trojan types: Remote Access Trojan (RAT), banking trojans, DDoS trojans
  • Ransomware variants: crypto-ransomware, scareware, locker ransomware
  • Rootkit detection and removal techniques
  • Fileless malware: living-off-the-land, PowerShell attacks, memory-only execution
  • Polymorphic and metamorphic malware techniques
  • Boot sector and macro viruses
  • Malware analysis methods: static vs dynamic analysis, sandboxing

Important Terms & Concepts

Virus: Malicious code that attaches itself to legitimate programs and requires human action (executing an infected file) to spread. Types: file infector, polymorphic, encryption, multipartite.
Worm: Self-replicating malware that spreads across networks without user interaction. Unlike viruses, worms do not need a host program (e.g., Conficker, WannaCry worm component).
Trojan (RAT): Malicious software disguised as legitimate. Remote Access Trojan (RAT) gives attackers full remote control: keylogging, screen capture, file access.
Ransomware: Encrypts victim's files and demands payment. Crypto-ransomware encrypts files. Scareware tricks users with fake alerts. Locker ransomware blocks system access.
Rootkit: Software that hides malware presence by intercepting OS calls at the kernel level. Can be user-mode or kernel-level. Detected via behavioral analysis and specialized tools (GMER, RootkitRevealer).
Fileless Malware: Operates entirely in memory without writing to disk. Uses legitimate tools like PowerShell and WMI. Extremely difficult to detect by traditional antivirus.
Polymorphic Malware: Changes its code/signature on each infection using encryption and mutation engines to evade signature-based detection. The decryptor stub remains constant.

How to Study This Module

  • Understand the key differences between viruses, worms, and trojans
  • Know each malware type's characteristics, infection methods, and detection techniques
  • Memorize ransomware variants and their specific behaviors
  • Understand fileless malware techniques — a major topic in CEH v13

Frequently Asked Questions

What is the difference between a virus and a worm?
A virus requires a host program and human action to spread. A worm is self-contained and replicates independently across networks without user interaction.

What is fileless malware?
Malware that operates entirely in memory without writing files to disk. It uses legitimate system tools (PowerShell, WMI) making it nearly invisible to traditional antivirus solutions.

What are Malware Threats in Ethical Hacking?

Malware Threats is a critical domain of the Certified Ethical Hacker v13 (CEH v13) exam administered by EC-Council. This module covers the complete taxonomy of malicious software — from legacy viruses and worms to modern APT campaigns, fileless threats, and double extortion ransomware. Ethical hackers must understand malware behavior to both develop effective attacks in authorized engagements and to design detection strategies for defenders. The CEH v13 exam emphasizes distinguishing between malware types by their propagation mechanism (host-based vs network-based), persistence technique, and evasion strategy. On the CEH v13 exam, questions related to Module 7 account for approximately 10% of total questions.

Key Concepts in Malware Threats

  • APT Campaign Lifecycle: Advanced Persistent Threat campaigns follow a structured kill chain: reconnaissance → weaponization → delivery → exploitation → installation → C2 → actions on objectives. Unlike opportunistic malware, APTs are targeted, resource-intensive, and maintained over months or years by nation-state or criminal actors. The CEH exam tests your ability to identify which stage of the kill chain a given TTP (Tactic, Technique, Procedure) belongs to and how each stage can be detected.
  • Botnet C2 Architecture: Botnets are networks of compromised machines controlled by a central command-and-control server. Modern botnets use DGA (Domain Generation Algorithms) to create thousands of fallback domains — even if some are blocked, the botnet can reconnect via newly generated domains. C2 communication protocols have evolved from IRC to HTTP(S)-based beacons with encrypted payloads and DNS tunneling. On the CEH exam, know how to detect botnet indicators: beaconing at regular intervals, anomalous outbound connections, DGA domain resolution patterns.
  • Ransomware Evolution & Double Extortion: Ransomware has evolved from simple file lockers to sophisticated double extortion attacks that exfiltrate data before encryption, creating two payment demands. Modern ransomware operations function as RaaS (Ransomware-as-a-Service), where developers provide the toolkit and affiliates handle targeting. The CEH exam tests understanding that backups alone are insufficient defense — egress filtering, DLP, and network segmentation are equally critical.
  • Fileless & Living-off-the-Land Malware: Fileless malware executes entirely in memory using legitimate system tools (PowerShell, WMI, CertUtil, MSHTA.exe) without dropping traditional executable files to disk. This makes signature-based antivirus nearly useless. Detection requires behavioral monitoring: anomalous PowerShell commands, encoded parameters, WMI event subscriptions, and process injection patterns. The CEH exam frequently tests identification of LOLBins (Living Off-the-Land Binaries) in attack scenarios.

Tools Used in Malware Threats

Malware analysis tools tested on the CEH exam include ANY.RUN and Joe Sandbox (interactive sandbox environments for safe dynamic analysis), VirusTotal (multi-engine AV scanning and threat intelligence), IDA Pro and Ghidra (disassemblers/decompilers for static analysis — Ghidra is free from NSA), x64dbg (debugger for dynamic analysis), and YARA (pattern-based malware identification using custom detection rules). For network-level malware detection, Suricata with community rules can identify C2 beaconing patterns. The CEH exam expects understanding of the analysis workflow: initial triage (hash lookup, VirusTotal) → static analysis (strings, PE headers, imports) → dynamic analysis (sandbox behavior, network connections, file system changes) → reporting and IOC extraction.

How to Study Malware Threats for the CEH v13 Exam

To effectively study Module 7 for the Certified Ethical Hacker exam:

  1. Create a comparison table of all malware types: virus (needs host + human), worm (self-replicating, no host), trojan (disguised, no replication), ransomware (cryptoware/extortion), rootkit (hiding), spyware (data theft) — the CEH exam frequently asks you to classify a described behavior

Frequently Asked Questions About Malware Threats

What is the difference between static and dynamic malware analysis on the CEH exam?

Static analysis examines the malware binary without executing it — inspecting PE headers, import tables, strings, sections, and disassembled code to identify suspicious behavior. It is safer (no execution risk) but can be defeated by packing, encryption, or polymorphism. Dynamic analysis executes the malware in a controlled environment (sandbox) and observes its runtime behavior: network connections made, files created/modified, registry keys added, processes spawned, and API calls made. On the CEH exam, the correct approach is always static first (safe triage), then dynamic (behavioral confirmation). Key exam tip: never perform dynamic analysis without a sandbox — malware can activate anti-analysis routines if it detects it's being debugged or run in VMs.

How do polymorphic and metamorphic malware differ?

Polymorphic malware uses an encryption engine to encrypt its payload with a different key each time it replicates, producing a different encrypted body each infection. However, the decryption stub (the code that decrypts the payload at runtime) remains constant — making it detectable by signature. Metamorphic malware is more advanced: it rewrites its entire code on each replication using code transformation techniques (instruction substitution, register reassignment, dead code insertion) without any encryption stub. Every copy is structurally different. On the CEH exam, the key distinction is: polymorphic = encrypted body + constant stub; metamorphic = fully rewritten code with no constant component. Both defeat signature-based detection but metamorphic is harder to detect even with behavioral analysis.
