CEH v13 Module 4: Enumeration

Enumeration actively engages a system to query it for information — routing tables, users, groups, machine names, network resources — to discover and exploit vulnerabilities. This module covers Windows enumeration, NetBIOS, SNMP, LDAP, NTP, SMTP enumeration, and Active Directory attacks.

Key Topics Covered

  • Difference between enumeration and scanning/footprinting
  • Windows enumeration: shares, null sessions, user accounts
  • Security Identifier (SID) format and common RID values
  • NetBIOS enumeration techniques and tools
  • SNMP community strings, OIDs, MIBs, and enumeration commands
  • LDAP hierarchical structure and information extraction
  • NTP enumeration for network reconnaissance
  • SMTP user enumeration via VRFY, EXPN, RCPT TO commands
  • Active Directory brute force techniques

Important Terms & Concepts

Enumeration: Actively engaging a system to extract user accounts, passwords, hashes, SMB info, SNMP data, and directory service information.
Null session: An anonymous connection allowing enumeration of machine configuration: net use \\target\\ipc$ \"\" /user: \"\"
SID format: S---- — e.g., S-1-5-21-...-500 = Administrator
Common RIDs: 500 = Administrator, 501 = Guest, 512 = Domain Admins, 513 = Domain Users
NetBIOS: Network Basic Input/Output System — naming system for Windows machines enabling file/printer sharing via SMB.
SNMP community strings: Read (public) = read-only access. Write (private) = full configuration access.
LDAP: Lightweight Directory Access Protocol — hierarchical structure: domain > child-domains > OUs > users/groups/computers.
SMTP enumeration commands: VRFY validates email addresses. EXPN reveals mailing list members. RCPT TO defines recipients.

Common Enumeration Ports

  • Port 25 — SMTP, Port 53 — DNS, Port 135 — RPC
  • Port 137/139 — NetBIOS, Port 161/162 — SNMP
  • Port 389 — LDAP, Port 445 — SMB/TCP
  • Port 514 — Syslog, Port 1433 — MSSQL, Port 3268 — Global Catalog

How to Study This Module

  • Know the SID format and common RID values (500, 501, 512, 513)
  • Understand SNMP v1/v2 vs v3 security differences
  • Practice SMTP enumeration command sequences (VRFY → EXPN → RCPT TO)

Frequently Asked Questions

What is the most critical RID to identify?
RID 500 — the Administrator account. It is the most powerful account on any Windows system.

How do you protect against SNMP enumeration?
Change default community strings, use SNMPv3 with encryption, and restrict SNMP access to authorized managers only.

What is Enumeration in Ethical Hacking?

Enumeration is an active information gathering technique in the Certified Ethical Hacker v13 (CEH v13) exam domain where attackers directly query target systems to extract usernames, machine names, network shares, group memberships, and other critical data. Unlike scanning (which identifies open ports), enumeration probes those open services with protocol-specific commands to pull structured information. This module covers Windows/SMB enumeration, NetBIOS name resolution, SNMP community string exploitation, LDAP directory traversal, NTP data extraction, and SMTP user validation. On the CEH v13 exam, questions related to Module 4 account for approximately 8% of total questions.

Key Concepts in Enumeration

  • Windows Null Session Enumeration: By connecting to a target's IPC$ share without credentials (net use \\target\\ipc$ \"\" /user:\"\"), an attacker can enumerate user accounts, group memberships, and machine names. The enum4linux tool automates this process. On the CEH exam, understanding what information null sessions expose — and how to disable them via registry or firewall rules — is a guaranteed question type.
  • SID and RID Identification: Windows Security Identifiers (SIDs) follow the format S-1-5-21--. The RID component identifies specific accounts: 500 = local Administrator, 501 = Guest, 512 = Domain Admins group, 513 = Domain Users group. Knowing these values is essential for identifying privilege escalation targets during enumeration.
  • SNMP Community Strings & OIDs: SNMP v1/v2 use plaintext community strings (default: public/read, private/write) that grant access to Management Information Bases (MIBs). By querying specific Object Identifiers (OIDs), an attacker can extract network topology, connected hosts, running services, and even OS versions. SNMPv3 addresses this with authentication and encryption.
  • SMTP User Enumeration: The VRFY command asks a mail server to confirm if a user exists, while EXPN reveals mailing list members. Combined with RCPT TO, these commands allow mapping an entire organization's email infrastructure. Modern servers often disable VRFY/EXPN, but the CEH exam still tests these protocol-level techniques.

Tools Used in Enumeration

Key enumeration tools include enum4linux (comprehensive Linux-based Windows enumeration), nbtstat (NetBIOS name queries), snmpwalk and snmpcheck (SNMP community string testing), ldapsearch (LDAP directory traversal), and responder (Poisoning attacks against SMB/NetBIOS). For SMTP enumeration, smtpuserenum or manual telnet sessions to port 25 are standard. In a hands-on lab environment with a Windows domain controller and Linux targets, practicing null session enumeration and SNMP community string discovery provides direct preparation for exam scenarios.

How to Study Enumeration for the CEH v13 Exam

Frequently Asked Questions About Enumeration

What is the difference between enumeration and scanning on the CEH exam?

Scanning (Module 3) identifies which ports are open and what services are running — it answers "what is accessible?" Enumeration (Module 4) goes deeper by sending protocol-specific commands to those services to extract actual data like usernames, group memberships, machine names, and network shares — it answers "what information can I extract from these services?" The CEH exam tests this distinction through scenario questions where you must identify whether a technique is scanning or enumeration based on the level of detail being gathered.

How does SNMP version 3 improve security over v1/v2?

SNMP v1 and v2c use plaintext community strings for authentication, meaning anyone who knows the string (often "public") can read or modify MIB data. SNMPv3 introduces three security models: noAuthNoPriv (no authentication), authNoPriv (authentication without encryption), and authPriv (authentication with AES/DES encryption). SNMPv3 also uses per-user credentials instead of shared community strings, making it significantly harder to enumerate. On the CEH exam, know that v3 is the recommended secure implementation and understand the three security levels.
