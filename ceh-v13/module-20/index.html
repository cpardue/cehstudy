CEH v13 Module 20: Cryptography

Cryptography is the foundation of information security. This module covers encryption algorithms (symmetric, asymmetric, hash), public key infrastructure (PKI), digital signatures, key management, cryptographic attacks, secure communication protocols, and wireless cryptography. Understanding these concepts is essential for ethical hackers to evaluate security postures and identify weaknesses.

Key Topics Covered

  • Cryptography fundamentals: plaintext, ciphertext, encryption, decryption, keys
  • Symmetric key algorithms: AES, DES, 3DES, Blowfish, ChaCha20, RC4
  • Asymmetric key algorithms: RSA, DSA, ECC, ElGamal, Diffie-Hellman
  • Cryptographic hash functions: MD5, SHA-1, SHA-256, SHA-3, BLAKE2, HMAC
  • Digital signatures: DSS, PKCS standards, ECDSA, signature process
  • Public Key Infrastructure (PKI): CAs, RAs, X.509 certificates, CRL, OCSP
  • Key management: distribution methods, lifecycle, HSM, key rotation
  • Cryptographic attacks: brute force, known/chosen plaintext, side channel, collision
  • Secure protocols: TLS/SSL, IPsec, SSH, PGP/GPG
  • Wireless cryptography: WEP, WPA, WPA2, WPA3

Important Terms & Concepts

Symmetric Encryption: Uses the same key for encryption and decryption. Fast and efficient for bulk data. Examples: AES (128/192/256-bit), DES (56-bit, broken), 3DES, Blowfish, ChaCha20. Modes of operation: ECB, CBC, CFB, OFB, GCM.
Asymmetric Encryption: Uses a public/private key pair. Public key encrypts, private key decrypts. Slower than symmetric but solves key distribution. Examples: RSA (2048-4096-bit), ECC (256-521-bit), DSA (signatures only), Diffie-Hellman (key exchange).
Cryptographic Hash Functions: One-way functions producing fixed-size digests. Properties: deterministic, pre-image resistant, collision resistant, avalanche effect. Secure: SHA-256, SHA-384, SHA-512, BLAKE2. Broken: MD5 (collisions), SHA-1 (SHAttered).
Digital Signatures: Provide authentication, integrity, and non-repudiation. Process: hash message → encrypt hash with sender's private key → append signature → receiver decrypts with sender's public key → compares hashes. Standards: DSS, PKCS#10, PKCS#7, ECDSA.
PKI (Public Key Infrastructure): Framework managing digital certificates and public-key cryptography. Components: Certificate Authority (CA) issues/signs certs, Registration Authority (RA) verifies requests, X.509 certificates bind identity to public key, CRL/OCSP for revocation checking.
Key Management: Covers key generation, distribution, storage (HSM, keystore), usage, rotation, revocation, and destruction. Methods: physical delivery, pre-shared keys (PSK), public-key encryption, Diffie-Hellman key exchange, KDC (Kerberos).
Cryptographic Attacks: Brute force (try all keys), known/chosen plaintext/ciphertext, collision attacks (two inputs → same hash), side channel (timing/power/EM leaks), man-in-the-middle, rubber hose coercion. Minimum key sizes: RSA 2048-bit, ECC 256-bit, AES 128-bit.
Secure Protocols: TLS/SSL (asymmetric handshake + symmetric data), IPsec (AH/ESP at network layer), SSH (ports 22, asymmetric auth + symmetric data), PGP/GPG (email/file encryption with combined symmetric+asymmetric).
Wireless Cryptography: WEP (RC4, broken), WPA (TKIP, deprecated), WPA2 (AES-CCMP, current standard), WPA3 (AES-GCMP/Suite B, forward secrecy). WPA3 introduces SAE (Simultaneous Authentication of Equals) replacing PSK.

How to Study This Module

  • Memorize the difference between symmetric and asymmetric encryption with specific algorithm examples
  • Know hash function strengths/weaknesses — which are broken (MD5, SHA-1) vs secure (SHA-256+, BLAKE2)
  • Understand the digital signature process step-by-step
  • Learn PKI components and how CAs, RAs, and certificates work together
  • Know minimum key size requirements for each algorithm type
  • Understand how secure protocols (TLS, IPsec, SSH) combine symmetric and asymmetric crypto

Frequently Asked Questions

Why is cryptography critical for ethical hackers?
Cryptography is the backbone of security. Ethical hackers must understand it to evaluate encryption strength, identify weak algorithms (DES, MD5), assess PKI configurations, and test protocol implementations for vulnerabilities.

What's the most important algorithm to know for the exam?
AES — it's the current symmetric standard. Also know RSA for asymmetric, SHA-256 for hashing, and the difference between WPA2 (AES) and WPA3 (forward secrecy).

How does PKI relate to digital certificates?
PKI is the entire framework that issues, manages, and revokes digital certificates. The CA signs certificates, RA verifies identities, and CRL/OCSP handle revocation. Certificates bind public keys to real-world identities.

What is Cryptography in Ethical Hacking?

Cryptography (Module 20) is arguably the most foundational domain on the Certified Ethical Hacker v13 (CEH v13) exam — it underpins virtually every other security control. On this exam, you're not expected to implement cryptographic algorithms from scratch, but you must be able to: identify which algorithm is in use, evaluate its strength against current attack capabilities, recognize when an algorithm is considered broken or deprecated, and understand how cryptographic protocols combine symmetric and asymmetric techniques in practice. Cryptography appears explicitly in Module 20 questions (approximately 8% of exam) but also appears implicitly throughout other domains — password hashing (Modules 5-7), wireless security (Module 16), protocol security (Modules 12-13), and digital signatures/certificates (throughout). On the CEH v13 exam, approximately 10-12 questions directly test cryptographic knowledge.

Key Concepts in Cryptography

  • Symmetric Encryption & AES: Symmetric ciphers use one key for both encryption and decryption. The exam focuses on AES (Advanced Encryption Standard) as the current standard: AES-128, AES-192, AES-256 variants with 128-bit block size. On the CEH exam, know the critical distinctions: (1) ECB mode is insecure for most use cases because identical plaintext blocks produce identical ciphertext blocks (reveals patterns — the famous "ECB penguin" example); (2) CBC mode adds an IV (Initialization Vector) for randomness but requires padding and is vulnerable to padding oracle attacks; (3) GCM (Galois/Counter Mode) provides both confidentiality AND integrity (authenticated encryption) in one operation — this is what TLS 1.3 uses by default. The exam also tests knowledge of deprecated algorithms: DES (56-bit key, broken by brute force since 1999), RC4 (keystream biases discovered, used in WEP and early TLS), and 3DES (still secure but being phased out due to 64-bit block size — Sweet32 birthday attack). For the exam: if a question mentions "bulk data encryption" the answer is almost always AES; if it mentions "deprecated but still found in legacy systems" think RC4 or DES.
  • Asymmetric Encryption & Key Exchange: Asymmetric algorithms use mathematically related key pairs. On the CEH exam, you must know: (1) RSA — most widely deployed asymmetric algorithm; used for both encryption (RSA-OAEP padding) and signatures (RSA-PSS or PKCS#1 v1.5); minimum 2048-bit keys recommended (NIST SP 800-57); 3072-bit for long-term security through 2030; (2) ECC (Elliptic Curve Cryptography) — provides equivalent security with much smaller keys: P-256 (256-bit curve) ≈ RSA-3072 security, P-384 ≈ RSA-7680; critical for IoT/mobile where key size matters; (3) Diffie-Hellman (DH) — key AGREEMENT protocol, not encryption; two parties derive shared secret without transmitting it; ECDHE (Elliptic Curve DHE) is the modern variant providing forward secrecy in TLS; (4) DSA (Digital Signature Algorithm) — signature-only algorithm (cannot encrypt); ECDSA is its elliptic curve equivalent. The exam frequently tests: "Which algorithm provides forward secrecy?" (Answer: ECDHE/DHE — not RSA, because RSA key exchange uses the server's long-term private key and a compromised key decrypts all past sessions). Forward secrecy means each session's keys are derived fresh and cannot be retroactively decrypted even if the long-term key is later compromised.
  • Cryptographic Hash Functions: Hash functions produce a fixed-size digest from variable-length input. The CEH exam tests properties: (1) Deterministic — same input always produces same output; (2) Pre-image resistance — given hash H, cannot find input M such that hash(M)=H; (3) Collision resistance — cannot find two different inputs M1≠M2 where hash(M1)=hash(M2); (4) Avalanche effect — 1-bit change in input should change ~50% of output bits. Secure algorithms: SHA-256 (256-bit), SHA-384, SHA-512, SHA-3 (Keccak-based), BLAKE2, BLAKE3. Broken/deprecated: MD5 (practical collision attacks since 2004 — MD Collide tool), SHA-1 (SHAttered proof-of-concept in 2017; NIST deprecated for digital signatures in 2013). On the CEH exam, know that MD5 and SHA-1 are STILL found in legacy systems and can be exploited: MD5 collision attacks can forge code signing certificates, and SHA-1 collisions have been demonstrated in certificate forgery. The practical implication: any system still accepting SHA-1 signatures is vulnerable to a chosen-prefix collision attack where an attacker creates a malicious certificate with the same hash as a legitimate one.
  • Digital Signatures & PKI: Digital signatures provide three security properties simultaneously: (1) Authentication — proves who signed; (2) Integrity — any modification invalidates the signature; (3) Non-repudiation — signer cannot deny having signed. The signing process: Hash(message) → Encrypt(hash, sender's PRIVATE key) → append signature. Verification: Decrypt(signature, sender's PUBLIC key) → Hash(received message) → compare. PKI components tested on CEH: (1) CA (Certificate Authority) — signs certificates, has root key; (2) RA (Registration Authority) — verifies identity before CA issues cert; (3) X.509 Certificate format — contains public key, subject/issuer DNs, validity period, serial number, signature algorithm; (4) CRL (Certificate Revocation List) — periodic file listing revoked serial numbers; (5) OCSP (Online Certificate Status Protocol) — real-time revocation checking (faster than CRL but introduces availability dependency); (6) AIA (Authority Information Access) — URLs for fetching issuer certs and CRLs. On the exam, know that certificate validation follows the chain: leaf cert → intermediate CA(s) → root CA, with each level verifying the signature of the next. A broken link at any point invalidates the entire chain.

Tools Used in Cryptographic Analysis

Cryptographic tools referenced on the CEH exam include OpenSSL (the definitive open-source cryptography toolkit: command-line interface for key generation [openssl genrsa, openssl ecparam], certificate operations [openssl req, openssl verify, openssl x509 -text], encryption/decryption [openssl enc -aes-256-cbc], and protocol testing [openssl s_client for TLS analysis]; the CEH exam expects you to recognize that OpenSSL is available on virtually all Unix/Linux systems and can be used to generate test keys/certs in authorized assessments); Wireshark (network protocol analyzer with built-in decryption capability: can decrypt TLS sessions if you provide the session key [Log → Export Session Keys from browser], decrypt IPsec ESP, analyze SSH handshake; essential for identifying weak cipher suites in use and detecting protocol downgrade attacks); hashcat (GPU-accelerated hash cracking tool supporting 300+ hash types: SHA-256/512 password hashes, NTLM, Kerberos (AES-128/256-CTS-HMAC-SHA1-96), WPA/WPA2 PSK (802.11 PMKID), and encrypted disk volumes; relevant to CEH because understanding hash strength informs password policy recommendations); TestSSL.sh (automated TLS configuration scanner checking for: weak cipher suites, protocol version support [TLS 1.0/1.1 deprecated], certificate chain validation, HSTS header presence, key size adequacy, and known vulnerabilities like Heartbleed/Logjam/BEAST); and FIDO2/WebAuthn security modules (hardware-based cryptographic key storage: TPM (Trusted Platform Module) on Windows for device attestation and BitLocker keys, Secure Enclave on Apple devices, FIDO2 tokens for passwordless authentication; relevant to CEH because understanding hardware-rooted key protection is part of modern key management strategy). On the CEH exam, know that OpenSSL is associated with key/certificate generation and Wireshark with protocol analysis.

How to Study Cryptography for the CEH v13 Exam

To effectively study Module 20 for the Certified Ethical Hacker exam:

  1. Create an algorithm reference table: Algorithm | Type (sym/asym/hash) | Key Size | Status (current/deprecated/broken) | Common Use. Include: AES-128/256 (sym, current, bulk encryption), RSA-2048/4096 (asym, current, key exchange + signatures), ECC P-256/P-384 (asym, current, IoT/mobile), ECDHE (key agreement, forward secrecy), SHA-256/384/512 (hash, current), SHA-3 (hash, current), BLAKE2/3 (hash, current), MD5 (hash, BROKEN), SHA-1 (hash, BROKEN for signatures), DES (sym, broken), 3DES (sym, deprecated), RC4 (sym/stream, broken), WPA2-AES (wireless, current standard), WPA3-SAE (wireless, forward secrecy). The exam frequently presents a scenario and asks which algorithm is being described or which one is appropriate
  2. Hands-on exercise: Use OpenSSL to generate an RSA key pair (openssl genrsa -out private.pem 2048), extract the public key (openssl rsa -in private.pem -pubout -out public.pem), create a self-signed certificate (openssl req -x509 -key private.pem -out cert.pem -days 365), and encrypt/decrypt a test file (openssl rsautl -encrypt / -decrypt). Then use openssl s_client to connect to a website and examine its TLS handshake: which cipher suite is negotiated? Which certificate chain is presented? Are any deprecated protocols (TLS 1.0/1.1) still offered? This directly mirrors exam questions about evaluating TLS configurations
  3. Memorize the "broken algorithms" list and why each is broken: MD5 — collision attacks (two different files with same hash → can forge signed files); SHA-1 — SHAttered chosen-prefix collision (can create malicious certificate matching legitimate one's hash); DES — 56-bit key space brute-forced in hours with modern hardware; RC4 — statistical biases in keystream allow plaintext recovery after observing sufficient ciphertext; WEP — IV reuse + weak CRC32 integrity check allows key recovery from ~40,000 packets. Know the specific attack name for each: MD Collide (MD5), SHAttered (SHA-1), Rainbow tables/distributed computing (DES/RC4), Flask/d4 protocol (WEP)
  4. Review related modules: Module 6 (System Hacking) for how cryptographic hashes are used in password storage and cracking (NTLM, Kerberos AES), Module 16 (Wireless Networks) for the full WEP→WPA→WPA2→WPA3 evolution with specific attack vectors for each, and Module 12 (Evading IDS/Network Attacks) for how encryption is used to hide malicious traffic from network-based detection systems. On the CEH exam, know that cryptography is a cross-cutting concern — it appears in nearly every domain

Frequently Asked Questions About Cryptography

What is forward secrecy and which protocols provide it on the CEH exam?

Forward secrecy (also called Perfect Forward Secrecy, PFS) is a property of key exchange protocols where each session's encryption keys are derived from ephemeral (temporary) key material that is destroyed after the session ends. This means that even if an attacker later obtains the server's long-term private key, they CANNOT decrypt previously captured session traffic. The key distinction on the CEH exam: Protocols WITH forward secrecy: (1) DHE (Diffie-Hellman Ephemeral) — RSA key exchange in TLS without DHE does NOT have forward secrecy because the server's RSA private key can decrypt past sessions; (2) ECDHE (Elliptic Curve DHE Ephemeral) — the modern standard providing forward secrecy with smaller keys; used in TLS 1.2 (ECDHE-RSA, ECDHE-ECDSA) and is the default in TLS 1.3 (which provides forward secrecy by design since RSA key exchange was removed entirely). Protocols WITHOUT forward secrecy: (1) RSA key transport in TLS — server's long-term RSA key encrypts the session master secret; compromise of this key decrypts ALL past sessions; (2) Static DH (non-ephemeral) — same shared secret used across all sessions with same parameters. On the CEH exam, know that TLS 1.3 mandates forward secrecy by removing static RSA key exchange — this is a significant security improvement over TLS 1.2 where non-forward-secret cipher suites were still negotiable. WPA3 also provides forward secrecy through its SAE (Simultaneous Authentication of Equals) mechanism, which uses ephemeral Diffie-Hellman for each association. The practical implication: an organization recording all network traffic (for compliance or malware analysis) is at risk if using non-forward-secret protocols — future key compromise reveals all recorded sessions.

How does a Man-in-the-Middle (MITM) attack exploit cryptographic protocols?

A MITM attack intercepts and optionally alters communication between two parties who believe they are directly communicating. On the CEH exam, know the specific cryptographic attack vectors: (1) Protocol downgrade — attacker forces both parties to use weaker protocol versions: SSLv3/TLS 1.0 instead of TLS 1.2/1.3 (enables POODLE/BEAST attacks), or CBC instead of GCM mode; detected by HSTS (HTTP Strict Transport Security) header and protocol version enforcement; (2) Certificate spoofing — attacker presents a self-signed or fake certificate; if the client does not properly validate the chain (or has the attacker's CA in its trust store), it accepts the connection; exploited via ARP spoofing on local networks to redirect traffic; (3) Key substitution in DH — attacker establishes separate key exchanges with each party (A↔M and M↔B), decrypting and re-encrypting all traffic; prevented by authenticated DH (where the DH public keys are signed, as in TLS); (4) Rogue CA attack — if an organization's trust store includes a compromised or unauthorized CA, any certificate from that CA is accepted; mitigated by certificate pinning (hardcoding expected public key hash in application). Detection methods: monitoring for unexpected certificate changes, certificate transparency logs (publicly searchable records of all issued certificates), HSTS preload lists, and network segmentation preventing rogue access points. On the CEH exam, the most commonly tested MITM scenario is ARP spoofing on a local network combined with TLS interception using a rogue CA — testing whether the organization properly validates certificates and uses HSTS.

Related CEH v13 Modules

  • Module 6: System Hacking — Cryptography (Module 20) is the theoretical foundation for password cracking in Module 6. When you crack NTLM hashes or Kerberos tickets, you're exploiting the cryptographic design of Windows authentication: NTLM's reliance on MD4-based NTOWFv1 hash (which allows offline brute force), Kerberos' use of AES-CTS-HMAC for ticket encryption (where key length determines cracking difficulty — AES-128 vs AES-256), and the fundamental property that hashes are one-way but finite in search space. On the CEH exam, know that understanding hash function properties (deterministic, fixed output length, avalanche effect) is what enables systematic password attacks: rainbow tables exploit determinism (same input → same output, precompute mappings), while GPU-based brute force exploits the finite key space
  • Module 16: Hacking Wireless Networks — The wireless security evolution is a direct application of cryptographic concepts to the 802.11 standard: WEP used RC4 with a 24-bit IV (insufficient for collision resistance — birthday paradox means IV reuse occurs after ~5,000 packets), WPA introduced TKIP as a stopgap (per-packet MIC but same RC4 core), WPA2 standardized AES-CCMP (Counter Mode + Cipher Block Chaining Message Authentication Code) providing both confidentiality and integrity, and WPA3 adds SAE (Simultaneous Authentication of Equals using Dragonfly key exchange) for forward secrecy and resistance to offline dictionary attacks. On the CEH exam, know that each wireless standard upgrade was driven by a specific cryptographic weakness in the previous generation
