CEH v13 Module 16: Hacking Wireless Networks

This module covers wireless network attacks including WEP/WPA/WPA2 cracking, evil twin attacks, rogue access points, deauthentication attacks, Bluetooth exploits, and Wi-Fi Protected Setup (WPS) attacks. Understanding wireless protocols is essential for both attacking and securing wireless infrastructure.

The CEHStudy app carries 13 flashcards for Module 16 across 2 sections — know the standard ladder cold: WEP is broken, WPA2 falls to handshake capture plus an offline dictionary attack, WPS PINs fall to Reaver in hours, and only WPA3 (SAE, plus protected management frames) removes both classic capture vectors.

Key Topics Covered

  • WEP cracking: IV collection, Aircrack-ng suite
  • WPA/WPA2-PSK: handshake capture and dictionary attacks
  • Evil twin attack: creating rogue AP with same SSID
  • Rogue access point deployment and detection
  • Deauthentication attacks to force reconnection
  • WPS PIN brute force (Reaver tool)
  • Bluetooth attacks: bluejacking, bluesnarfing, BlueBorne

Important Terms & Concepts

WEP (Wired Equivalent Privacy): Oldest and weakest Wi-Fi security. Uses RC4 with static IVs. Crackable in minutes using Aircrack-ng. Completely broken — never use.
WPA/WPA2-PSK: Pre-Shared Key authentication using TKIP (WPA) or AES (WPA2). Vulnerable to handshake capture + dictionary/brute-force attacks. WPA2 is the minimum acceptable standard.
Evil Twin: Rogue AP broadcasting the same SSID as a legitimate network. Used for MITM attacks, credential harvesting, and traffic interception. Often deployed with deauth to force client association.
Rogue AP: Unauthorized access point connected to a secured network. Can be an employee's home WiFi or a malicious device. Creates a backdoor into the internal network.
Deauthentication Attack: Sends deauth frames to disconnect clients from an AP. Forces reconnection so attacker can capture the WPA handshake for offline cracking. Tools: aircrack-ng, mdk3.
WPS (Wi-Fi Protected Setup): Convenience feature with PIN-based authentication. Vulnerable to brute force — Reaver can recover WPS PIN in hours, then crack the PSK. Disable WPS on all APs.

How to Study This Module

  • Know WEP vs WPA vs WPA2 security levels and crackability
  • Understand the evil twin attack flow: create AP → deauth clients → MITM
  • Memorize wireless attack tools: aircrack-ng suite, Reaver, Kismet, Wireshark

Frequently Asked Questions

Which Wi-Fi security is easiest to crack?
WEP is the easiest (minutes). WPA2-WPS is next if WPS is enabled (hours). WPA2 without WPS requires capturing the handshake then offline dictionary/brute-force attack.

What is an evil twin attack?
Creating a rogue access point with the same SSID as a legitimate network. Victims connect automatically, and the attacker performs MITM to capture traffic and credentials.

What is Wireless Network Hacking in Ethical Hacking?

Wireless Network Hacking is a dedicated domain on the Certified Ethical Hacker v13 (CEH v13) exam administered by EC-Council. This module covers attacks against Wi-Fi (802.11) wireless networks — the encryption protocols (WEP, WPA, WPA2, WPA3), management frame security, and convenience features like WPS that create attack vectors. Unlike wired network attacks where physical access to cabling is required, wireless attacks can be performed remotely within radio range — making them both more accessible and more dangerous. The attacker's goal ranges from gaining network access (cracking the Wi-Fi password) to full man-in-the-middle interception (evil twin + deauth). On the CEH v13 exam, questions related to Module 16 account for approximately 8% of total questions.

Key Concepts in Hacking Wireless Networks

  • WEP Cracking & RC4 IV Vulnerability: WEP (Wired Equivalent Privacy) secures Wi-Fi using RC4 stream cipher with a 24-bit initialization vector (IV) prepended to each encrypted packet. The fundamental flaw: the IV is transmitted in cleartext and reused frequently, allowing attackers to collect enough IVs to perform statistical analysis of the RC4 key stream. Aircrack-ng's attack requires approximately 5-10 million IVs for a 64-bit WEP key (achievable in minutes on busy networks) or ~200,000 IVs for 128-bit keys (still feasible with deauth-assisted traffic generation). On the CEH exam, know that WEP is broken at the protocol level — no amount of password complexity makes it secure. The specific RC4 weakness is the "FMS attack" (Fluhrer, Mantin, Shamir) which exploits statistical biases in the first bytes of RC4 output when certain IV patterns occur. WPA replaced WEP specifically because TKIP/AES cannot be attacked this way.
  • WPA2 Handshake Capture & Dictionary Attack Flow: The WPA2-PSK attack requires: (1) Capturing the 4-way handshake between a client and AP — the attacker uses deauthentication frames to force a client to reconnect, triggering a new handshake; (2) Running an offline dictionary/brute-force attack against the captured handshake using tools like Aircrack-ng or Hashcat. The 4-way handshake proves both parties know the PSK without transmitting it in cleartext — but the handshake contains a Message Integrity Code (MIC) that can be verified offline by guessing the PSK. On the CEH exam, know that the attack is offline (no interaction with target after capture) and success depends entirely on password strength. A 12-character random alphanumeric password has ~69^12 = 10^22 possible combinations — effectively uncrackable. Common passwords like "password" or "welcome1" are cracked in seconds. WPA3's SAE (Dragonfly) handshake eliminates this vulnerability by never exposing values that can be used for offline guessing.
  • Evil Twin & Deauthentication Attack Chain: The complete evil twin attack flow: (1) Reconnaissance — identify target SSID, BSSID (MAC address), and security type using airmon-ng and airodump-ng; (2) Put wireless adapter in monitor mode (airmon-ng start wlan0); (3) Deploy rogue AP with identical SSID and higher signal strength (using hostapd or a USB Wi-Fi dongle); (4) Send deauthentication frames to all clients on the legitimate AP (aircrack-ng --deauth) — this disconnects them and forces reconnection; (5) Clients automatically associate with the rogue AP (same SSID, stronger signal); (6) Perform man-in-the-middle — capture credentials, inject malicious content, or relay traffic. On the CEH exam, know that 802.11 management frames (deauth, authentication, association) are NOT encrypted in WPA2 — anyone within radio range can forge them. WPA3's PMF (Protected Management Frames) addresses this specific vulnerability by encrypting and authenticating management frames.
  • WPS PIN Brute Force & Reaver: Wi-Fi Protected Setup uses an 8-digit PIN, but the verification protocol splits it: first half (4 digits) and second half (4 digits) are verified independently with separate checksums. This reduces the attack space from 10^8 to approximately 11,111 (10^4 for first half + 9,999 for second half, accounting for checksum). Reaver automates this brute force, typically recovering the PIN in 2-12 hours. Once the WPS PIN is known, the attacker can either connect using WPS or derive the WPA PSK. On the CEH exam, know that WPS should be disabled on all production access points — the convenience of plug-and-pair vastly increases attack surface. Detection: unusual reconnection patterns, WPS LEDs blinking repeatedly, or monitoring for Reaver's characteristic request patterns (typically 3 requests per minute per PIN attempt).

Common Exam Mistakes in Module 16

Confusing PMKID capture with the full 4-way handshake: the PMKID is available from the initial EAPOL exchange, so it can be captured without forcing a reassociation at all — then cracked offline with hashcat. The classic handshake flow (deauth a client, capture the 4-way handshake, crack with a wordlist) is a different, slower path. Both attack WPA2-Personal and both end in the same place: the pre-shared key.
Counting MAC filtering and hidden SSIDs as real controls: MAC addresses are trivially spoofed and a hidden SSID is still visible to any scanner — the defensible stack on the exam is WPA2-AES (or WPA3) with a long random PSK, WPS disabled entirely, firmware kept current, 802.1X/RADIUS enterprise authentication where available, guest Wi-Fi segmented, and rogue APs hunted with WIDS/WIPS.
Forgetting why deauthentication works at all: 802.11 management frames are not encrypted or authenticated, so any device within radio range can forge a deauth frame using the victim's MAC — that single fact powers handshake capture, wireless denial of service, and evil-twin setup in one move. WPA3's PMF (Protected Management Frames, 802.11w) signs management frames, which is why the attack dies on WPA3 with PMF enabled.

Tools Used in Wireless Network Hacking

Wireless attack and analysis tools the CEH v13 exam references, by job:

  • Aircrack-ng suite: the primary wireless toolkit — airmon-ng puts the adapter in monitor mode, airodump-ng captures traffic and handshakes, aireplay-ng generates deauthentication, and aircrack-ng cracks WEP/WPA keys offline against a wordlist
  • Reaver: automated WPS PIN brute-forcer that runs in the background, recovers the 8-digit PIN by exploiting its weak per-digit checksum (around 11,000 combinations offline), and derives the PSK once the PIN is found
  • Kismet: passive wireless detector and sniffer — finds rogue APs, hidden SSIDs, and non-standard channels without transmitting a single packet
  • mdk3 / mdk4: multi-function attack tool covering deauthentication, fog attacks against WPA, fake authentication frame injection, and channel hopping
  • Cowpatty: precomputed-attack cracker for PMKID hashes — trades disk space (rainbow tables of PMKIDs) for cracking speed when a station is connected or the SSID is known
  • Wireshark: packet analyzer for dissecting captured 802.11 frames — examining handshake structure and spotting protocol anomalies after capture
  • Honeyd: transparent proxy used in evil twin setups to redirect client traffic so interception is invisible to the victim

Worked Example: From Deauth to Cracked PSK, One Network at a Time

airmon-ng start wlan0 puts the adapter in monitor mode, where it sees every frame in range regardless of BSSID. airodump-ng then identifies the target — SSID, BSSID, channel, WPA2-PSK security — and aireplay-ng --deauth floods the legitimate AP: because management frames are unauthenticated, connected clients drop instantly and reassociate, emitting a fresh 4-way handshake into the capture file. Offline, aircrack-ng -w wordlist.txt handshake.cap tests candidates at hardware speed; a strong random PSK survives this, which is exactly why the hardening checklist leads with key entropy and killing WPS.

The twist: if the same AP has WPS enabled, the faster path is Reaver against the PIN — the per-digit checksum collapses the search to roughly 11,000 offline combinations, and the recovered PIN yields the PSK without ever touching the handshake. And on WPA3 the chain breaks twice: SAE resists the offline dictionary attack on the handshake, and PMF makes the deauth frame itself unforgeable — so an exam stem that specifies WPA3 with PMF enabled has removed both the fuel and the trigger.

  3. Memorize the deauth → reassociate → handshake → crack pipeline as a sequence: (1) Identify target BSSID, (2) Set monitor mode on same channel, (3) Send 20-50 deauth frames to force disconnect, (4) Capture new association + 4-way handshake, (5) Run offline dictionary attack. Frequently Asked Questions About Wireless Network Hacking

What is a deauthentication attack and why is it important on wireless networks?

A deauthentication attack involves sending forged 802.11 management frames (deauth/disassoc) to a wireless client or access point, causing immediate disconnection. In WPA2, management frames are NOT encrypted or authenticated — any device within radio range can forge them using the victim's MAC address. The attack is critical because: (1) It forces connected clients to reassociate, triggering a new 4-way handshake that the attacker can capture for offline cracking; (2) It disrupts wireless service (denial of service); (3) It makes evil twin attacks more effective by clearing the air so clients must choose an AP — the rogue one with stronger signal wins. On the CEH exam, know that deauth is both an attack and a defensive concern — WPA3's PMF (Protected Management Frames, 802.11w) requires cryptographic authentication of all management frames, making forgery impossible without the pairwise key. The practical implication: if you see repeated disconnections on a corporate Wi-Fi network, check for deauth attacks using airmon-ng monitoring or the AP's built-in rogue client detection features.

How does an evil twin attack work step by step?

Complete evil twin attack flow: (1) Reconnaissance — use Kismet or airodump-ng to identify the target network's SSID, BSSID (MAC), channel, and security protocol. Note signal strength of the legitimate AP; (2) Prepare rogue AP — configure a second Wi-Fi adapter (or USB dongle) with the same SSID, matching encryption type (WPA2-PSK in most cases), and optionally the same BSSID (spoofing) if clients use MAC-based selection. Use hostapd + wpa_supplicant on Linux, or turnkey tools like Wifite; (3) Deploy — position the rogue AP with higher signal strength than the legitimate one (antenna gain or closer proximity); (4) Deauth — send deauthentication frames to all currently connected clients on the legitimate AP using aireplay-ng --deauth or mdk3. This disconnects them and forces reassociation; (5) Client association — disconnected clients scan for available networks and automatically connect to the SSID with the strongest signal (the rogue AP); (6) MITM execution — the rogue AP now controls all traffic: can serve a captive portal with fake login pages, perform SSL stripping on HTTP traffic, inject JavaScript into HTTPS via certificate spoofing, or relay traffic to a transparent proxy. On the CEH exam, the key vulnerability exploited is that 802.11 uses SSID (not BSSID) for network selection in most client implementations — two APs with the same SSID are indistinguishable by name alone.
