Directory Traversal

Directory Traversal (Path Traversal) is a vulnerability that allows an attacker to access files and directories outside the intended web root directory by manipulating file path parameters with sequences like ../ (Unix) or ..\ (Windows). When exploited for reading sensitive files, it is also called Local File Inclusion (LFI). Remote variants where the server fetches external resources are called Remote File Inclusion (RFI).

Types & Variations

  • Local File Inclusion (LFI) — Server reads local filesystem files via path manipulation: ../../etc/passwd, ../../boot.ini, C:\Windows\win.ini
  • Remote File Inclusion (RFI) — Server fetches and includes a remote file via URL: http://attacker.com/shell.php (requires allow_url_include enabled)
  • Null Byte Injection — Appends %00 to truncate path validation: ../../etc/passwd%00.jpg passes .jpg filter but OS stops at null byte
  • URL Encoding Bypass — Double-encoding (%252e%252e%252f) or Unicode encoding to bypass WAF/path filters

Common Tools & Techniques

Burp Suite (path traversal testing) Commix Custom scripts with various encoding variants

Ethical hackers and security professionals use these tools in authorized penetration tests and red team operations. Unauthorized use is illegal under the Computer Fraud and Abuse Act (CFAA) and equivalent legislation worldwide.

Real-World Examples

LFI: /page?file=../../../etc/passwd — server resolves to /etc/passwd, response shows Unix user accounts
Windows: /page?file=..\..\..\..\windows\win.ini — reveals Windows configuration
Bypass: /page?file=....//....//....//etc/passwd — double-slash encoding bypasses filter looking for ../

How Directory Traversal Appears on the CEH v13 Exam

Directory traversal is covered in CEH v13 Module 14 (Hacking Web Applications). The exam tests understanding of path resolution mechanisms on Linux vs Windows, how web servers handle relative vs absolute paths, null byte handling differences across OS versions, WAF bypass techniques (encoding, case manipulation, null bytes), prevention strategies (canonicalizing paths, using allowlists for accessible files, running as unprivileged user, disabling RFI in PHP configuration), and identifying vulnerable parameters in application code. Questions may present file path strings for traversal attempt identification.

Prevention & Detection

  • Input Validation: Implement strict allowlist-based input validation on all user-facing parameters
  • Principle of Least Privilege: Run applications with minimum required permissions
  • Regular Patching: Maintain timely vulnerability management and patch deployment
  • Network Segmentation: Limit lateral movement through zone-based network architecture
  • Monitoring & Alerting: Deploy SIEM/SOAR solutions with threat detection rules for anomalous activity
