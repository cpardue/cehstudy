ARP Spoofing

ARP Spoofing (also called ARP Cache Poisoning) is a Layer 2 attack where an attacker sends forged Address Resolution Protocol (ARP) messages onto a local network to associate their MAC address with the IP address of another device (typically the default gateway). This causes all traffic destined for that IP to be routed through the attacker, enabling man-in-the-middle interception.

Types & Variations

  • Dynamic ARP Spoofing — Continuously sends forged ARP replies/gratuitous ARPs at regular intervals to maintain cache poisoning (tools: ettercap, arpspoof)
  • Gratuitous ARP — Unolicited ARP response broadcast claiming "IP X is at MAC Y" without being asked; most effective as it updates caches on all listening hosts
  • Off-link ARP Spoofing — Exploits router/proxy ARP functionality to spoof addresses on different subnets (requires specific network configuration)
  • ARP Rebinding — Used in LAN attacks (Fyodor's technique) where attacker rebinds all observed IPs to their own MAC after each new IP is detected

Common Tools & Techniques

ettercap (GUI/CLI) arpspoof (Dug Song) Bettercap (arp.spoof module) cain & abel

Ethical hackers and security professionals use these tools in authorized penetration tests and red team operations. Unauthorized use is illegal under the Computer Fraud and Abuse Act (CFAA) and equivalent legislation worldwide.

Real-World Examples

Gateway Spoof: Attacker sends gratuitous ARP "192.168.1.1 (gateway) is at MAC aa:bb:cc:dd:ee:ff" — all hosts update their ARP cache, traffic now flows through attacker
ettercap Targeted: ettercap -T -i eth0 -M "arp /192.168.1.50/ replace_with aa:bb:cc:dd:ee:ff" 192.168.1.1 192.168.1.50 — poisons only specific victim
Detection: Monitor shows gateway IP mapped to two different MAC addresses across hosts — indicates active ARP spoofing

How ARP Spoofing Appears on the CEH v13 Exam

ARP spoofing is covered in CEH v13 Module 08 (Sniffing and Traffic Analysis) as a primary sniffing technique. The exam tests understanding of ARP protocol mechanics (ARP request/reply format, cache table structure, gratuitous ARP), how to detect ARP poisoning (monitoring for duplicate IP-to-MAC mappings, comparing ARP tables across hosts), defensive countermeasures (Dynamic ARP Inspection on managed switches, static ARP entries on critical systems, port security), and the limitations of ARP spoofing (only works on same Layer 2 broadcast domain/VLAN). Questions may present ARP cache outputs for anomaly identification.

Prevention & Detection

  • Input Validation: Implement strict allowlist-based input validation on all user-facing parameters
  • Principle of Least Privilege: Run applications with minimum required permissions
  • Regular Patching: Maintain timely vulnerability management and patch deployment
  • Network Segmentation: Limit lateral movement through zone-based network architecture
  • Monitoring & Alerting: Deploy SIEM/SOAR solutions with threat detection rules for anomalous activity

Related Glossary Terms
