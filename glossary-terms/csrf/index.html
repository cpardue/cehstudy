CSRF (Cross-Site Request Forgery)

Cross-Site Request Forgery (CSRF) is an attack that forces an authenticated user's browser to send unintended requests to a trusted application. The attacker crafts a malicious request (form submission, link click, image load) that is automatically sent with the victim's valid session cookies, causing actions to be performed as if the victim initiated them.

Types & Variations

  • Unforced Content CSRF — Uses auto-submitting HTML forms or hidden image tags; requires no user interaction beyond page load
  • Forced Content CSRF — Requires deliberate user action (clicking a link or pressing Enter on a pre-filled form) to trigger the forged request
  • JSON CSRF — Exploits applications accepting JSON POST requests without CSRF token validation
  • Multi-step CSRF — Attacks applications with multi-step workflows by crafting intermediate state transitions

Common Tools & Techniques

Burp Suite (CSRF token testing) CSRF PoC generator Browser dev tools (manual form crafting)

Ethical hackers and security professionals use these tools in authorized penetration tests and red team operations. Unauthorized use is illegal under the Computer Fraud and Abuse Act (CFAA) and equivalent legislation worldwide.

Real-World Examples

Fund Transfer: Attacker hosts
with hidden fields (to=attacker_account, amount=$1000) that auto-submits when victim visits page while logged in
Account Deletion: GET request to /profile/delete — no CSRF token check; attacker's image tag triggers deletion when victim is authenticated
State Change: POST /settings with {"two_factor":false} — disables 2FA for victim if application lacks SameSite=Lax cookie setting

How CSRF (Cross-Site Request Forgery) Appears on the CEH v13 Exam

CSRF is covered in CEH v13 Module 14 (Hacking Web Applications). The exam tests understanding of the CSRF mechanism (browser automatically includes cookies with same-origin requests), distinction between CSRF and XSS (XSS executes attacker code; CSRF uses victim's own browser to send requests), prevention strategies (anti-CSRF tokens with unique per-session values, SameSite cookie attribute Lax/Strict, verifying Origin/Referer headers, requiring re-authentication for sensitive actions), and how to identify vulnerable endpoints. Questions may present HTML/code samples for vulnerability identification.

Prevention & Detection

  • Input Validation: Implement strict allowlist-based input validation on all user-facing parameters
  • Principle of Least Privilege: Run applications with minimum required permissions
  • Regular Patching: Maintain timely vulnerability management and patch deployment
  • Network Segmentation: Limit lateral movement through zone-based network architecture
  • Monitoring & Alerting: Deploy SIEM/SOAR solutions with threat detection rules for anomalous activity

Related Glossary Terms

  • Cross-Site Scripting (XSS) — XSS can be used to bypass CSRF protections by reading tokens
  • Man-in-the-Middle Attack — Both exploit the browser's trust model
