Port Scanning

Port Scanning is a network reconnaissance technique used to identify open ports, running services, and their versions on a target system by sending crafted packets to specific port numbers and analyzing responses. It is one of the first steps in any penetration test or cyberattack, providing the attacker with an attack surface map.

Types & Variations

  • TCP SYN Scan (Half-Open) — Sends SYN, if SYN/ACK received port is open; if RST received port is closed; never completes 3-way handshake — faster and stealthier
  • TCP Connect Scan — Completes full TCP 3-way handshake; slower but works without raw socket privileges; logged in application logs
  • UDP Scan — Sends UDP packets to ports; open = response or ICMP unreachable; closed = ICMP port unreachable; filtered = no response
  • FIN Scan — Sends packet with only FIN flag set; open/closed ports respond RST, filtered ports drop packet — bypasses stateless firewalls
  • NULL Scan — Packet with no flags set; similar to FIN but some systems respond differently to empty-flag packets
  • XMAS Scan — Packet with URG, PSH, and FIN flags set (resembles Christmas lights); same detection logic as FIN scan

Common Tools & Techniques

Nmap (primary), Masscan (fast UDP/ICMP sweeps) Zenmap (Nmap GUI) Netcat (nc) for manual port checks Angry IP Scanner

Ethical hackers and security professionals use these tools in authorized penetration tests and red team operations. Unauthorized use is illegal under the Computer Fraud and Abuse Act (CFAA) and equivalent legislation worldwide.

Real-World Examples

SYN Scan: nmap -sS target.com — sends SYN to ports 1-65535; if SYN/ACK returned, port open (attacker sends RST instead of ACK)
Service Version: nmap -sV -p 80,443,3306 target — identifies web server type/version and database engine
OS Detection: nmap -O target — analyzes TCP/IP stack responses to determine operating system (Windows responds differently to certain probes than Linux)

How Port Scanning Appears on the CEH v13 Exam

Port scanning is the foundation of CEH v13 Module 03 (Scanning Networks). The exam tests understanding of TCP/IP packet flag behavior for each scan type, when to use stealth scans vs connect scans, Nmap command syntax and options (-sS, -sT, -sU, -sF, -sN, -sX, -A, -p, --top-ports), detection via IDS signatures (Suricata/Snort rules for SYN floods on non-standard ports), and evasion techniques (fragmentation, decoys, timing adjustments, OS fingerprinting). Questions may present packet captures for scan type identification.

Prevention & Detection

  • Input Validation: Implement strict allowlist-based input validation on all user-facing parameters
  • Principle of Least Privilege: Run applications with minimum required permissions
  • Regular Patching: Maintain timely vulnerability management and patch deployment
  • Network Segmentation: Limit lateral movement through zone-based network architecture
  • Monitoring & Alerting: Deploy SIEM/SOAR solutions with threat detection rules for anomalous activity

Related Glossary Terms

  • Network Enumeration — Port scanning precedes service enumeration
  • Denial of Service — Aggressive port scans can trigger or mimic DoS conditions
