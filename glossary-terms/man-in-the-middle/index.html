Man-in-the-Middle Attack

A Man-in-the-Middle (MitM) Attack is a technique where an attacker secretly intercepts and potentially alters communication between two parties who believe they are directly communicating with each other. The attacker positions themselves between the communicating endpoints to eavesdrop, modify, or inject data without detection.

Types & Variations

  • ARP Spoofing — Sends forged ARP replies claiming the attacker's MAC address corresponds to the gateway IP, causing traffic to route through the attacker
  • DNS Poisoning/Spoofing — Corrupts DNS cache (on victim or resolver) with malicious IP mappings, redirecting legitimate domain names to attacker-controlled servers
  • SSL Stripping — Downgrades HTTPS connections to HTTP before TLS negotiation begins, enabling plaintext interception
  • BGP Hijacking — Injects false BGP routes into the global routing table, diverting entire network prefixes through attacker infrastructure
  • Rogue Access Point (Evil Twin) — Creates a wireless network with same SSID as legitimate one; victim associates and traffic flows through attacker

Common Tools & Techniques

ettercap / etterfilter Bettercap dnsspoof sslstrip Cain & Abel

Ethical hackers and security professionals use these tools in authorized penetration tests and red team operations. Unauthorized use is illegal under the Computer Fraud and Abuse Act (CFAA) and equivalent legislation worldwide.

Real-World Examples

ARP Spoofing: Attacker on same subnet sends gratuitous ARP claiming 192.168.1.1 (gateway) has attacker MAC — all traffic now passes through attacker
SSL Stripping: User types example.com — attacker intercepts redirect to https:// and strips it back to http:// before the page loads
Session Hijack via MitM: Attacker captures JSESSIONID cookie over intercepted HTTP connection, replays it to impersonate authenticated user

How Man-in-the-Middle Attack Appears on the CEH v13 Exam

MitM attacks are covered in CEH v13 Modules 08 (Sniffing and Traffic Analysis) and 11 (Session Hijacking). The exam tests knowledge of Layer 2-7 interception techniques, how to detect MitM (certificate pinning, HSTS, network monitoring), the mechanics of ARP cache poisoning, DNS hijacking variants, and TLS-specific attacks (BEAST, POODLE as enablers). Questions often present network topology diagrams for attack feasibility assessment.

Prevention & Detection

  • Input Validation: Implement strict allowlist-based input validation on all user-facing parameters
  • Principle of Least Privilege: Run applications with minimum required permissions
  • Regular Patching: Maintain timely vulnerability management and patch deployment
  • Network Segmentation: Limit lateral movement through zone-based network architecture
  • Monitoring & Alerting: Deploy SIEM/SOAR solutions with threat detection rules for anomalous activity
