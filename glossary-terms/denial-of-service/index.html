Denial of Service (DoS)

A Denial of Service (DoS) Attack is a malicious attempt to make a system, network, or service unavailable to legitimate users by overwhelming it with traffic, exploiting resource exhaustion vulnerabilities, or corrupting configuration. A Distributed DoS (DDoS) uses multiple compromised systems (botnet) to amplify the attack volume beyond what a single source can generate.

Types & Variations

  • Volume-based Attacks — Saturate bandwidth: UDP floods, ICMP floods, DNS amplification (can reach 100Gbps+ via botnets)
  • Protocol-based Attacks — Exploit implementation weaknesses: SYN flood (exhausts connection table), Ping of Death, Smurf attack (amplified ICMP)
  • Application-layer (Layer 7) Attacks — Target specific application logic: HTTP GET floods, Slowloris (holds connections open with slow headers), R-U-Dead-Yet (RUDY), resource-intensive queries
  • Amplification/Reflection Attacks — Leverage protocols where response is larger than request: DNS (54x), NTP (556x), memcached (51,000x), CLDAP (260x)
  • HTTP/2-specific — Rapid Reset attack exploits HPACK compression to send massive concurrent streams that crash servers

Common Tools & Techniques

hping3 LOIC / HOIC Slowloris (custom script) Botnet C2 frameworks (for study/lab use)

Ethical hackers and security professionals use these tools in authorized penetration tests and red team operations. Unauthorized use is illegal under the Computer Fraud and Abuse Act (CFAA) and equivalent legislation worldwide.

Real-World Examples

SYN Flood: Attacker sends millions of SYN packets with random spoofed source IPs — server allocates resources for half-open connections until table is full
DNS Amplification: Spoofed-source DNS query for a large record (ANY type) sent to open resolvers — response (54x larger) goes to victim IP
Slowloris: Opens hundreds of HTTP connections, sends partial headers slowly — server keeps all connections waiting, exhausting thread pool

How Denial of Service (DoS) Appears on the CEH v13 Exam

DoS/DDoS is CEH v13 Module 10. The exam tests understanding of all three attack categories (volume, protocol, application), specific named attacks (SYN flood mechanics with half-open connections, amplification factors for DNS/NTP/memcached), and mitigation strategies including rate limiting, connection pooling, DDoS scrubbing services (Cloudflare, Akamai), SYN cookies, and BGP flow specifications. Questions may present packet captures or attack logs for classification.

Prevention & Detection

  • Input Validation: Implement strict allowlist-based input validation on all user-facing parameters
  • Principle of Least Privilege: Run applications with minimum required permissions
  • Regular Patching: Maintain timely vulnerability management and patch deployment
  • Network Segmentation: Limit lateral movement through zone-based network architecture
  • Monitoring & Alerting: Deploy SIEM/SOAR solutions with threat detection rules for anomalous activity
