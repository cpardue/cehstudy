Module 14: Cryptography

Section 1: Cryptography Fundamentals

Cryptography = the science of securing information through transformation into unreadable format.

Key Concepts

  • Plaintext: Original readable message/data
  • Ciphertext: Encrypted/encoded message
  • Encryption Algorithm (Cipher): Mathematical process to convert plaintext to ciphertext
  • Decryption Algorithm: Process to convert ciphertext back to plaintext
  • Key: Secret value used by encryption algorithm

Cryptographic Goals (CIA Triad)

  • Confidentiality: Only authorized parties can access information
  • Integrity: Data has not been altered unauthorizedly
  • Availability: Information accessible when needed
  • Authentication: Verifying identity of communicating parties
  • Non-repudiation: Sender cannot deny sending message

Section 2: Symmetric Key Cryptography

Symmetric encryption uses the same key for both encryption and decryption.

Common Symmetric Algorithms

  • DES: 56-bit block cipher - BROKEN
  • 3DES (Triple DES): 112/168 bits - Deprecated
  • AES: 128/192/256-bit block cipher - Current standard (Rijndael)
  • Blowfish: 32-448 bit key size, block cipher
  • ChaCha20: 256-bit stream cipher, used in TLS 1.3
  • RC4: Stream cipher - BROKEN (RFC 7465)

Block vs Stream Ciphers

  • Block ciphers: Encrypt fixed-size blocks (64/128 bits). Modes: ECB, CBC, CFB, OFB, GCM
  • Stream ciphers: Encrypt data one bit/byte at a time continuously

Section 3: Asymmetric Key Cryptography

Asymmetric encryption uses a pair of keys: public key (encryption) and private key (decryption).

Common Asymmetric Algorithms

  • RSA: Based on integer factorization. 2048-4096 bit keys. Widely used.
  • DSA: Discrete logarithm. Signatures only. 2048-3072 bits.
  • ECC: Elliptic curve cryptography. 256-521 bits. Modern, efficient.
  • Diffie-Hellman: Key exchange algorithm. Vulnerable to MITM without authentication.

RSA (Rivest-Shamir-Adleman)

Most widely used public-key algorithm. Used in SSL/TLS, digital signatures, SSH.

Section 4: Hash Functions

Cryptographic hash functions convert input data to fixed-size digest. One-way function.

Common Hash Algorithms

  • MD5: 128-bit digest - BROKEN (collisions found)
  • SHA-1: 160-bit digest - BROKEN (SHAttered attack)
  • SHA-256: 256-bit digest - Secure. Used in Bitcoin, TLS.
  • SHA-384/SHA-512: Larger variants of SHA-2 family
  • BLAKE2: Secure and fast modern alternative

Hash Function Properties

  • Deterministic: Same input always produces same output
  • Pre-image resistant: Cannot reverse hash to find original data
  • Avalanche effect: Small change = large difference in output
  • Collision resistant: Hard to find two inputs with same hash

HMAC (Hash-based Message Authentication Code)

Combines hash function with secret key. Provides both integrity and authentication.

Section 5: Digital Signatures

Digital signatures provide authentication, integrity, and non-repudiation.

Digital Signature Process

  1. Sender creates message hash using hash function
  2. Hash encrypted with sender's private key (digital signature)
  3. Signature appended to message and sent
  4. Receiver decrypts signature with sender's public key
  5. Receiver computes own hash of received message
  6. Hashes compared - if match, signature valid

Digital Signature Algorithms: DSS, PKCS #10, PKCS #7/CMS, ECDSA

Section 6: Public Key Infrastructure (PKI)

PKI = framework for managing public-key cryptography through certificates and CAs.

PKI Components

  • Certificate Authority (CA): Trusted entity that issues digital certificates
  • Registration Authority (RA): Verifies certificate requests
  • Digital Certificate: Binds identity to public key (X.509 format)
  • Certificate Revocation List (CRL): List of revoked certificates
  • OCSP: Online Certificate Status Protocol for real-time revocation checking

X.509 Certificate Fields: Version, Serial Number, Signature Algorithm, Issuer, Validity Period, Subject, Subject Public Key, Signature Value

PKCS Standards

  • PKCS #1: RSA cryptography
  • PKCS #5: Password-based encryption
  • PKCS #7: Cryptographic message syntax (CMS)
  • PKCS #10: Certificate signing request format
  • PKCS #12: Personal information exchange (.pfx files)

Section 7: Key Management

Key Distribution: Physical delivery, Pre-shared keys (PSK), Public-key encryption, Diffie-Hellman, KDC (Kerberos)

Key Lifecycle: Generation → Distribution → Storage → Usage → Rotation → Revocation → Destruction

Section 8: Cryptographic Attacks

  • Brute Force: Try all possible keys
  • Known/Chosen Plaintext: Attacker has access to plaintext-ciphertext pairs
  • Collision Attack: Find two inputs producing same hash
  • Side Channel: Exploit timing, power consumption, electromagnetic leaks
  • Man-in-the-Middle: Intercept and modify communications

Minimum Key Size Requirements: RSA 2048 bits, ECC 256 bits, AES 128 bits, SHA-256 minimum

Section 9: Protocols Using Cryptography

  • TLS/SSL: Asymmetric handshake + symmetric data transfer
  • IPsec: Network-layer encryption (AH, ESP)
  • SSH: Port 22, asymmetric auth + symmetric encryption
  • PGP/GPG: Email/file encryption with digital signatures

Section 10: Wireless Cryptography

  • WEP: RC4 - BROKEN
  • WPA: TKIP/RC4 - Deprecated
  • WPA2: AES-CCMP - Current standard
  • WPA3: AES-GCMP - Latest, forward secrecy

Section 11: Notable Cryptographic Incidents

Flame Malware (2012)

Spoofed Microsoft Windows Update signatures by stealing a legitimate certificate.

Stuxnet (2010)

Used four stolen digital certificates to spread. Targeted Siemens SCADA systems.

Heartbleed (CVE-2014-0160)

OpenSSL vulnerability allowing memory disclosure. Exposed private keys and passwords.

Snowden Revelations (2013)

Revealed NSA's backdoored Dual_EC_DRBG random number generator, mass surveillance.
