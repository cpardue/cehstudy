CEH v13 Module 14: Hacking Web Applications

Web applications are prime targets for attackers due to their widespread availability and frequent exposure to the internet. This module covers common web application vulnerabilities, OWASP Top 10 risks, and attack techniques that ethical hackers must understand to evaluate and improve web application security.

OWASP Top 10 (2021)

1. Broken Access Control: Restrictions enforcing the intended security policy are missing or ineffective. Examples: unauthorized access to other users' data, accessing admin functions without privilege, bypassing authorization.
2. Cryptographic Failures: Failure to protect sensitive data per requirements. Examples: transmitting credit card numbers, PI, passwords in clear text, weak or nonexistent encryption. See Module 20: Cryptography for detailed coverage.
3. Injection: Untrusted data is sent as part of a command or query. Examples: SQL injection, NoSQL injection, OS injection, LDAP injection. SQLi remains the most critical and common.
4. Insecure Design: Missing or ineffective control design. Examples: lacking threat modeling, using unsafe third-party components, insufficient business logic controls.
5. Security Misconfiguration: Incorrect configuration of security settings. Examples: default credentials, unnecessary features enabled, verbose error messages, missing security headers.
6. Vulnerable and Outdated Components: Using components with known vulnerabilities. Examples: outdated libraries, unsupported frameworks, unpatched dependencies.
7. Identification and Authentication Failures: Attacks related to authentication. Examples: brute force, credential stuffing, session fixation, weak password policies.
8. Software and Data Integrity Failures: Unauthorized code or data influence. Examples: insecure CI/CD pipelines, unsigned deserialization, unverified updates.
9. Security Logging and Monitoring Failures: Insufficient logging and monitoring. Examples: lack of real-time monitoring, no incident response, delayed breach detection.
10. Server-Side Request Forgery (SSRF): Attacker sends crafted requests from the server itself to bypass access controls. Can be used to scan internal networks or access cloud metadata.

SQL Injection (SQLi)

What is SQL Injection? A technique where malicious SQL statements are inserted into input fields to manipulate the backend database. Types: In-band (Classic), Blind (Boolean-based, Time-based), Out-of-band.
SQLi Examples: ' OR '1'='1 — bypasses login. '; DROP TABLE users; -- — destructive attack. ' UNION SELECT username, password FROM users -- — data extraction.
Prevention: Use parameterized queries/prepared statements, input validation, least privilege database accounts, WAF (Web Application Firewall), ORM frameworks.

Cross-Site Scripting (XSS)

What is XSS? Injecting malicious client-side scripts into otherwise benign web pages. Types: Stored (persisted on server), Reflected (from URL parameters), DOM-based (client-side only).
XSS Impact: Session hijacking, credential theft, defacement, malware distribution, keylogging, phishing.
Prevention: Output encoding, Content Security Policy (CSP) headers, input validation, HttpOnly and Secure cookie flags, modern frameworks with auto-escaping.

Cross-Site Request Forgery (CSRF)

What is CSRF? Forcing an authenticated user to perform unwanted actions on a web application. The attacker tricks the victim's browser into making requests to a trusted site where they're logged in.
Prevention: Anti-CSRF tokens, SameSite cookie attribute, verifying Origin/Referer headers, requiring re-authentication for sensitive actions.

Session Attacks

Session Hijacking: Taking over a user's authenticated session by stealing or predicting the session ID. Techniques: network sniffing, XSS, side-channel attacks, brute force.
Session Fixation: Attacker sets a known session ID for the victim before authentication. After login, the attacker uses the same session ID.
Prevention: Regenerate session IDs after login, use Secure and HttpOnly flags, implement session timeout, bind sessions to IP/user agent (carefully).

Frequently Asked Questions

Why is SQL injection still critical in 2026?
Despite awareness, SQLi remains common due to legacy codebases, improper input validation, and developers using string concatenation instead of parameterized queries.

What tool do ethical hackers use for web app testing?
Common tools include Burp Suite (proxy and vulnerability scanner), OWASP ZAP (free alternative), sqlmap (SQLi automation), and OWASP Top 10 checklist.
